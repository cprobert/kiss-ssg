Every commit is in the operator's name with a Claude co-author trailer, so authorship settles nothing; the session logs' record of who decided does. Claude re-checked two findings against the files: the version quote (`planning/sessions/2026-09-26-flaky-discard-staging-test.md:38`, "settled by the operator") and `4aad440`, a "Consolidate" commit with no operator approval recorded.

This is the evidence for a later branch on which **the operator decides each rule**: keep, cut or reword. Nothing here changes a rule by itself.

## The root cause

`/memory-consolidate` turns a lesson that recurs in two or more reflections into a binding rule in `CLAUDE.md` or a ritual step, and `retired.md` says nothing is ever removed from it. So rules only grow, each with a dated list of incidents, and none needs the operator's yes.

## Other rules that look AI-derived and costly

All promoted by `/memory-consolidate`, none with an operator decision in `retired.md`: "verify an edit landed before committing it"; "after the first finding, fix the class, not the case" (and "the suite is a sibling too"); "a conclusion drawn from a command needs its exit code and its stderr"; "check nothing is serving a folder before building into it"; "a command for the operator goes on its own line"; the `/branch-pulse` cadence ("Claude offers it at least once per working session"); and the one-decision offer as an `AskUserQuestion` in `/branch-pulse`.

Not AI-derived: "upstream is documented, not engineered around" comes from an operator quote ("If there are upstream errors … document and live with them").
