# Round-four output-path correction

Measured locally, Node 24.14.0 on Windows x64, three fresh processes per scenario,
median build phase. Main is bf6878d. Before is ec94a9f; after is the uncommitted
round-four correction atop ec94a9f (the harness records HEAD, not a dirty suffix).
All runs used the same installed dependencies and did not overlap test execution. The first main attempt was run from the active cwd, which mislabeled its
Git revision; the committed main record is the rerun from the main checkout.

Command for each checkout: `node scripts/bench.mjs --pages=500,2000 --runs=3
--scenario=scan,fanout --json=<record>` (the command is a single line).

| Scenario    |    Main |  Before |   After | After vs main |
| ----------- | ------: | ------: | ------: | ------------: |
| scan@500    |  702 ms |  879 ms |  737 ms |         +5.0% |
| fanout@500  |  490 ms |  648 ms |  495 ms |         +1.1% |
| scan@2000   | 2566 ms | 5000 ms | 2652 ms |         +3.3% |
| fanout@2000 | 1758 ms | 4088 ms | 1760 ms |         +0.1% |

The getter cache and hoisted comparison remove the multi-second build regression.
Small remaining differences are not attributed to a particular mechanism.
The cache is invalidated by all supported route setters and by buildDir promotion.
Raw records are the three adjacent round4 JSON files. These are historical evidence,
not a baseline for another machine or day. Browser latency was not measured here.

The final after record includes the independent write-boundary safety recheck.
