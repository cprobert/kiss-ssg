# Plan — `config.ids: 'path'`: a page's default id is where it is served

- **Status:** design, 2026-11-05, on `feat/page-ids-and-embed-poster` (criterion #3). It is critiqued by a fresh-context agent before any code is built against it, and amended in place with dated sections.
- **Requested by:** diploma-msc (kiss-ssg 2.12). It has 686 pages, and 123 of them had no usable default id, including all 104 `/p/` course pages, because its catalog chooses the view per item. The site now gives every page an explicit `id` equal to its served path. That is the convention it wanted from kiss.

## What is true today (read from `lib/`, 2026-11-05)

- **The default id is the view's route.** `page-registry.js` `defaultIdForView`: `blog/listing.hbs` → `blog/listing`, `menu/index.hbs` → `menu/index`, `index.hbs` → `index`. An inline template (a view that is not a `.hbs` name) has no default id.
- **A fan-out item's default id** is `<idPrefix>/<written slug>` (`preparePage`). The prefix is the registration's `id`, else its view route.
- **Two pages arriving at one default id** both have it withdrawn (`idIndexFor`). It is `null` in the report, `none` in the site map, and a `{{link}}` to it fails, with one notice per id. Pagination (two `.page()` calls on one view) and a catalog that picks views per item both land here.
- **An explicit id** (a non-empty string from `.page()`, a record or a controller, `explicitIdOf`) wins over a default one. Two explicit claims on one id fail the build.
- **The served path** is `KissPage.pageURL()`: `<path>/<slug>.<ext>`, or `<path>/<slug>/index.<ext>` under `extensionLess` (except a slug of `index`). `utils.toURLKey` reduces it to the policy-free page key used for `isActive`.
- **Readers of an id**: `{{link}}` (`lookupPage`) and its `slug=` sugar (`<id>/<toSlug(slug)>`); the report's `pages[].id`; the AIKB site map's `Id` column; `last-build.json`'s `moved` pairing (by id across two builds); the privacy page found by id (`audit.privacyPage ?? 'privacy'`); `config.consent.ui.policy` / `ui.history` (page ids); a learning package's member identifier (`package-manifest.js`, from the id alone).

## The design

**One config key, `ids`, with two values: `'view'`, the default and today's behaviour, and `'path'`.** It sits at the top level, not under `links`, because an id is read by more than `{{link}}` (packages, the privacy page, consent, the site map). Any other value throws when the `Kiss` is constructed, naming the two allowed values, as `audit.ignore` does with an unknown check. It is site-wide only, with no per-page override, because a mixed site would have two conventions for one namespace.

**Under `'path'`, a page's default id is its served location as a key:** `pageURL()` with a trailing `.html` removed, then a trailing `/index` removed. The home page is `index`.

| Written to (`pageURL()`)                | `ids: 'path'` default id   | `ids: 'view'` today (view `x.hbs`)             |
| --------------------------------------- | -------------------------- | ---------------------------------------------- |
| `index.html`                            | `index`                    | `index`                                        |
| `about.html`                            | `about`                    | `about`                                        |
| `about/index.html` (`extensionLess`)    | `about`                    | `about`                                        |
| `courses/index.html` (`menu/index.hbs`) | `courses`                  | `menu/index`                                   |
| `c/acute-medicine-courses.html`         | `c/acute-medicine-courses` | `search/static-courses/acute-medicine-courses` |
| `feed.xml`                              | `feed.xml`                 | (its view)                                     |
| `data/index.json`                       | `data/index.json`          | (its view)                                     |

- **Only `.html` is removed.** It is the extension the served URL hides (`{{link}}` writes `/about.html` or `/about/`, and a person names the page `about`). A non-HTML page keeps its extension, so `about.html` and `about.json` never compete for `about`.
- **`index` for the home page, not `''`.** An empty id is not an id: `explicitIdOf` refuses it, and `{{link ""}}` is a mistake rather than a name. `index` is also what the home page is called under `'view'`, so `{{link "index"}}` means the same thing in both modes.
- **Fan-out items get a path id too.** The registration's `id` is then not used as a prefix, because the path already says where the item is. A `.pages()` call that gives an `id` under `'path'` logs one notice per registration saying that it is ignored, rather than silently dropping it. A record's own `id` and a controller's `id` are explicit and still win.
- **Inline templates and pages that share a view get ids.** Two pages cannot share an output path (the duplicate-output check already fails that), so path ids collide only where two outputs reduce to one key: `about.html` and `about/index.html` in one build (a per-page `extensionLess` override). That uses the existing withdrawal: both are withdrawn, with a notice.
- **`generate: false` still claims no id.** It has no served path.
- **The id is computed where it is today**, in `preparePage` after `kissPage.prepare()`, from `preparedPage.pageURL()`. That is where the written slug and the path are both known.

## What changes for the readers

- **`{{link}}`:** `{{link "c/acute-medicine-courses"}}`. The `slug=` sugar keeps its meaning (`<id>/<toSlug(slug)>`), so `{{link "blog" slug=post.slug}}` reaches a fan-out item written under `blog/`. Under `'path'` the sugar's first argument is a path prefix, not a view route. The GUIDE says so.
- **`last-build.json` `moved`:** a page moved under `'path'` changes its default id with its path, so it reads as `removed`, as a renamed fan-out item already does today. `moved` follows explicit ids only. The GUIDE says this under § Redirects.
- **Switching a site from `'view'` to `'path'`** changes every default id that differs, and nothing else: no output path, no page byte except a `{{link}}` the author rewrites. Things to check on the switch, which go in the upgrade note: every `{{link "<view route>"}}` that names a differing id (the build fails on each one, so the site cannot ship with a stale one), `consent.ui.policy`/`ui.history` and `audit.privacyPage` if they name such an id, and **any learning-package page relying on a default id, whose LMS identifier changes, so its learners' records are lost**. A package page should carry an explicit id in either mode, and the GUIDE already says the id is a promise.
- **The first `last-build.json` diff after a switch** compares by path for `removed`, so it reports nothing false. `moved` pairs by id, and with every id changed it pairs nothing, which is correct.
- **AIKB site map:** the `Id` column shows the path ids. It is regenerated by the next `kiss-ssg aikb`.

## Tests (each seen red first)

1. Unit `defaultIdForPath(pageURL)` (pure, `page-registry.js`): the table above, including `extensionLess`, the home page, a nested index, `.xml`/`.json`, and a path with a leading `/`.
2. Integration: under `ids: 'path'`, two `.page()` calls on one view (pagination) and a catalog that picks views per item both get ids, and `{{link}}` resolves each one.
3. Integration: a fan-out under `'path'` gives `blog/<slug>` from `path: 'blog'`. A registration `id` is ignored with one notice. A record `id` wins.
4. Integration: the collision `about.html` + `about/index.html` withdraws both, with a notice.
5. Integration: `ids: 'view'` and an unset `ids` are byte-identical to today on an existing example. Config validation throws on `ids: 'paths'`.
6. Integration: the report's `pages[].id` and the AIKB site map carry the path ids.

## Non-goals

- Changing the default (`'view'`) for any site that does not opt in.
- A per-page `ids` override.
- Rewriting a site's `{{link}}` calls on the switch. The build fails on each stale one, and that is the worklist.
- Normalising explicit ids (criterion #2 decided: warn, do not rewrite).

## Amendment, 2026-11-05: after the fresh-context critique

A fresh agent read this plan against `lib/` before any code was written. Its eight findings were checked locally (1 and 2 against `page-registry.js:539` and `redirects.js:501-519`), and all eight are taken. Where this section and the design above disagree, this section wins.

1. **An engine-invented slug gives no path id.** An inline template with no `slug` gets `snippet-<random>` (`page-registry.js:539`). Its path id would churn on every build and replay, through the report, the AIKB site map and `last-build.json`. That branch sets a flag on the options, `slugInvented`, carried as engine bookkeeping on the stack entry rather than as an own key of `options`, and an invented slug claims no default id in either mode. A prefix test (`snippet-`) is not used.
2. **The report records the mode, and `moved` pairs ids only within one mode.** `moved` pairs by the id string alone, so after a switch a different page can carry the same id (`index` was `landing.hbs` writing `home.html`, and is now the home page), and the build reports a false "moved without redirect". `BuildReport` gains `ids: 'view'|'path'`, appended after `audit`. `redirectFindings` skips id pairing when the last record's `ids` (absent means `'view'`) differs from this build's. The path-only `removed` still runs.
3. **The switch checklist names the two defaults.** `consent.ui.policy` defaults to `'cookies'`, and the audit finds the privacy page by the id `'privacy'`. A `cookies.hbs` or `privacy.hbs` written under a `path` changes id on the switch. For the banner that fails the render; for `privacy-link-missing` it produces an advisory finding.
4. **A plain collision.** `{ path: 'courses', slug: 'index' }` (`courses/index.html`) and `{ slug: 'courses' }` (`courses.html`) both reduce to `courses` with no `extensionLess` anywhere. The withdrawal handles it, and test 4 covers this case.
5. **A non-HTML page under `extensionLess`** is written to `<x>/index.<ext>` (`kiss-page.js:230`), so its path id is `feed/index.xml`. That is honest, because it is served at `/feed/index.xml` (`servedPathFor` collapses only `index.html`). It is stated in the GUIDE and tested. The table's `feed.xml` row holds only without `extensionLess`.
6. **Read `kiss.config.ids`, never `options.config.ids`.** A per-page `config: { ids }` is ignored, and a test shows it.
7. **AIKB notes cite page ids** (`aikb.js:501`), so after a switch a note citing an old view id is reported as `dangling`. That goes in the switch checklist.
8. **Watch:** `_replay()` resets `_idNoticed`, so the "registration id ignored" notice repeats once per whole-site rebuild. That is accepted and stated in the AIKB doc.

Confirmed as written: `index` for the home page (strip `/index$` anchored on the slash, never `toURLKey`'s `(^|\/)index$`, so the root does not become `''`); only `.html` removed (a `.htm` page keeps `.htm`); `ids` at the top level; a throw on an unknown value; and computing the id from `preparedPage.pageURL()` in `preparePage`.
