# kiss-ssg gap analysis — what a site builder still has to build themselves

Date: 2026-09-05 · Branch: `review/v2-critical-friend` · Informative only: no owners, no sequencing, no sprint.

Sources: the v2 design (`planning/specs/2026-09-02-v2-solid-refactor-design.md`), the watch spec
(`planning/specs/2026-09-05-watch-dependency-graph-design.md`), the engine in `lib/`, and a real consumer, read-only, at `/home/user/diploma-msc` (~200 pages, Firebase-hosted, on `kiss-ssg ^1.4.4`,
`/home/user/diploma-msc/package.json:295`).

## 1. What kiss-ssg is for

kiss-ssg is a **small, dependency-driven MVC generator**: Handlebars views, models that are a JSON
file / a folder of JSON / an object / a URL, and JS controllers that reshape options
(`llms.txt:3`, `llms.txt:9`). Its whole surface is ten chainable methods and one config object
(`planning/specs/2026-09-02-v2-solid-refactor-design.md:40-49`). There is no build step, no bundler
and no transpilation (`CLAUDE.md:5`); the consumer supplies the data, the templates and the
deployment, and kiss turns registrations into files. v2 was a _structural_ release — decompose into
one-responsibility modules, add Vitest, move to ESM, fix four determinism defects — and its Non-goals
section is explicit: **"No new SSG features beyond the additive `close()` / `watch({ entry })`"** and
"no change to the build pipeline's shape" (`:78-85`). The watch spec repeats the posture: measure
before building anything traced, and "stopping there is the cheap and respectable outcome"
(`planning/specs/2026-09-05-watch-dependency-graph-design.md:9`, `:150`).

So the yardstick below is **not Astro or Eleventy**. A gap here means one of two things: (a) a general
static-site concern that every kiss consumer must re-solve in their own repo, where owning it inside
`lib/` would be smaller than the code it deletes downstream; or (b) an inconsistency the engine
already implies but does not deliver (a documented config key nothing reads, a sitemap the consumer
still hand-rolled). Anything that is genuinely _this site's_ business — its CMS, its CDN, its
redirects, its Cloud Functions — is correctly outside, and is tagged as such rather than counted
against the product.

`this._stack`) because the public surface did not expose what it needed; v2's `.sitemap()` closes
that particular one.

## 4. Three recommendations

**O5 — canonical and absolute-URL helpers (S).** A new pair of built-ins in
`lib/handlebars-helpers.js`, `{{canonical}}` and `{{absUrl path}}`, resolving `config.siteUrl`
against the page's own `pageURL` with exactly the normalisation `isActive` already performs
(`AIKB/handlebars-helpers.md:29`: drop leading/trailing slash, extension and trailing `index`). No
new module, no new dependency, and it reuses the one config key `.sitemap()` already requires
(`lib/sitemap.js:44`). The evidence is that the consumer wrote it once and then had to keep the same
domain constant in three unrelated files (`modules/handlebars-helpers.js:102`,
`modules/llms/urls.js:26-31`, `modules/faculty-tutors.js:4`), and the version in the template does
its own `.replace('/index.html','')` string-surgery that the engine already knows how to do
correctly. Ships with unit cases in `test/unit/handlebars-helpers.test.js` (extensionless on and
off, home page, a `siteUrl` with a trailing slash) and two rows in `llms.txt` § Helpers.

**O6 — cache-busted asset URLs (S/M).** `lib/assets.js` already walks every asset it copies
(`lib/assets.js:35-48`), so it can return a manifest of `source → emitted` alongside its `{id,data}`
result, and one `{{asset "css/site.css"}}` helper can read it. Content hash or `config.version`
suffix is a one-line policy; the important part is that the _template_ stops encoding the scheme.
Today the consumer runs a grunt task that renames whole output folders (`gruntfile.js:134-151`) and
every stylesheet reference interpolates `{{config.name}}-{{config.version}}` by hand
(`src/layouts/layout.hbs:37`) — meaning a template edit is required to change a caching policy. Keeps
one responsibility per module (`assets.js` emits, the helper reads), needs `AIKB/assets.md` updated
in the same commit, and the manifest must be per-instance state so two `Kiss` instances in one
process stay isolated (`AIKB/kiss.md:43`).

**D6 — a fetch policy for URL models (M).** `resolveModel`'s HTTP branch is a bare
`fetchImpl(model)` (`lib/model-resolver.js:33`): no headers, no auth, no timeout, no retry, no
caching. That is why the strongest consumer evidence in this document is an _absence_ — diploma-msc
has an HTTP data source and wrote 1191 lines of `get-data-orchard.js` rather than use the feature.
The proposal keeps `model-resolver.js`'s single responsibility and adds one config block
(`config.fetch: { headers, timeout, retries, cache }`), plus an on-disk cache under a dot-folder
keyed by URL so a watch rebuild stops paying a network round trip per remote model
(`AIKB/kiss.md:53`) and an offline `npm run dev` still builds. `fetchImpl` is already the injected
seam the unit tests use (`AIKB/model-resolver.md:33`), so timeout/retry/cache-hit/stale-on-error are
all testable without a network. Two consumer-visible notes for `llms.txt` and `README.md`: a cached
model is a _build input_, and the non-2xx guard (`lib/model-resolver.js:34`) stays authoritative over
the cache.

## 5. What is deliberately NOT missing

- **A CMS, a data layer, an image service.** `get-data-orchard.js` (1191 lines) is the consumer's
  business, not the generator's. The v2 stance is a generator whose model is "JSON file / folder /
  object / URL" (`llms.txt:9`); D5 and D6 sharpen that seam rather than moving the seam.
- **A bundler.** `gruntfile.js`'s concat/uglify/PurgeCSS/spritesmith/cwebp chain is exactly what
  "no build step, bundler, or transpilation" (`CLAUDE.md:5`) declines to own. Kiss compiles Sass and
  copies (`lib/assets.js:35-40`) and minifies HTML/CSS/JS in the page it wrote
  (`lib/kiss-page.js:115-118`); that is the whole intended footprint. O6 is a _URL_ concern, not a
  bundling one, which is why it stays in scope while the rest does not.
- **Host configuration.** 250 redirects, header rules, `cleanUrls` and rewrites live in
  `firebase.json` because they are the host's contract, not the site's output. Owning a
  redirect-format matrix would put kiss in the deployment business (O3).
- **Template-engine pluralism and i18n.** Handlebars + `handlebars-layouts` is the product
  (`README.md:5`), and the alternative is an abstraction layer the v2 spec explicitly refused to
  invent (`…v2-solid-refactor-design.md:18-20`). No consumer here has asked for either.
- **A traced dependency graph for watch mode.** Already correctly deferred: the no-graph fast path
  is unconditionally correct (`AIKB/kiss.md:78`) and step 3 is gated on a measurement nobody has
  taken (`…watch-dependency-graph-design.md:128`). Building it now would be optimising an unmeasured
  cost — the same reasoning that keeps P2 in "measure first".
- **Model and controller scoping in rebuilds.** The watch spec's Non-goals section
  (`…watch-dependency-graph-design.md:38`) lists five concrete regression mechanisms; nothing in the
  consumer's code argues against that reasoning.
