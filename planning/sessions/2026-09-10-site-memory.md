# Session — 2026-09-10: Site memory — a build-generated AIKB, a check diff, and the `kiss-memory` plugin

## Intent (captured at /branch-open)

**Objective:** Make a kiss site carry its own memory: the engine writes the structural half of a site's knowledge base from the build (`kiss.aikb()`), `kiss-ssg check --against` makes "this change touched exactly these pages" checkable, and a second marketplace plugin (`kiss-memory`) ships the site-shaped open/pulse/close loop plus a "catch me up" briefing that reads it all back — so a developer returning after years, or a second developer joining, is briefed in minutes rather than rediscovering the site.

Full design and contract: `planning/plans/2026-09-10-site-memory.md`.

**Success criteria:**

- [ ] `kiss.aikb()` writes `AIKB/README.md` (once), `site-map.md`, `site-map.json`, `last-build.json`, byte-stable across identical builds; under `KISS_CHECK` it computes but writes nothing; the report carries `aikb: { folder, written, notes: { missing, dead } }`; the missing/dead rules hold on a fixture with one of each; example 8 commits a generated `AIKB/` with one note.
- [ ] Every generated page carries `hash` in the report; `kiss-ssg check --against <report>` prints added / removed / changed / unchanged in JSON and summary modes, pairs reports by `buildDir`, reads JSON Lines, a JSON array or a single report, and treats a missing file as a usage error; exit code unaffected.
- [ ] `plugins/kiss-memory/` with `kiss-catch-up`, `kiss-open`, `kiss-pulse`, `kiss-close`; second entry in the marketplace; version sync and the manifest test cover every plugin; the rubric copy is identity-tested; `.claude/skills/branch-open` reads back recent Feedback.
- [ ] Every new `lib/` module has a unit test and an AIKB doc in the same commit; `llms.txt`, `README.md`, `CLAUDE.md`'s table and `types/` updated; `npm run gates` green.

**Non-goals / out of scope:** a strict flag failing `check` on missing notes; note-heading enforcement; moving this repo's own skills onto the new plugin; a version bump, CHANGELOG entry or PR (the close does those when asked).

**Impact surface:** public API — a new method, a new `folders` key, two new report keys, a new `check` option, a second plugin. Obliges `llms.txt` + `README.md` + `types/`; the bump the close proposes is minor.

**Expected shape:** planned — three workstreams with a written contract; B and C concurrent, A after B; Fable reviews each diff before it is committed.

**Delegation convention:** Fable briefs, reviews and commits; agents implement, write to disk as they go and never commit.

# Session Reflection — 2026-09-12: Site memory — from a radical idea to a recorded knowledge base, three amendments in

_A Claude Code session is supervised collaboration: Claude generates, the human directs and judges. The session's quality is set by how actively the human supervised it. This reflection reads that supervision, as CPD for both._

**What we shipped:** 25 commits (`d57753e` … the 2.1.1 bump) on `claude/skills-marketplace-aikb-concept-fs01nd`, 86 files, version 2.1.1. ## Reflect — what the session was

**Emergent, then planned in three beats.** It opened as a conversation, not a brief: the operator brought a "radical idea" — ship the branch ceremony and a self-documenting AIKB through the marketplace — and asked for critique and creativity in the same breath. The critique held (the ceremony and the site skills are two products; the engine's AIKB is a module-contract schema, not a second brain; a knowledge base nobody reads back is a diary), and the reframing that followed — "how could kiss help me get back up to speed on a site I last touched six years ago?" — produced the actual product: the engine writes the structural half, people write the why, the ceremony reads it back. From there the work was planned: a written contract in `planning/plans/`, three workstreams built against it by delegated agents, and Fable reviewing every diff before it was committed.

The plan then bent three times, each time on the operator's word and each time recorded as a dated amendment rather than a new branch. The first bend was the important one. The landed design had `.aikb()` writing the folder on every build; the operator's concern — "it has to be done over an entire development session, not a rebuild" — exposed the flaw that the baseline the diff compared against moved every time anyone built, so the diff answered "since my last build" rather than "since I opened this work". The method was removed, the record became a command run only by the close, and the API got smaller. The second bend added the consistency lints and consolidation the operator wanted shipped now rather than as a later engine upgrade across client sites. The third ported the lessons back into this repo's own skills and ran the new consolidation on the repo's own logs as its dogfood. Planned shape served the building; emergent shape served the deciding. The session needed both and got them in the right order.

## Evaluate — how the human supervised the AI

**Pushback & steering is where this session was won.** Three steers, all the operator's, all decisive. "I'm afraid you lost me" after the first counter-proposal forced a rewrite from abstraction into a scenario a returning developer could recognise, and that rewrite is the design. The baseline concern reversed a landed feature within a day of it landing, and was right. The naming convention (`thing-action`) was imposed late and applied everywhere, at a cost of one commit and no regret. None of these was absorbing the first answer; each changed what got built.

**Problem framing** started open by design and tightened as the operator learned what they wanted. The initial ask was a critique, not a spec, and that was the right ask: the plan written after the second exchange had a contract precise enough for two agents to build against concurrently without treading on each other, and the contract's amendments carried the same precision. The one framing gap worth naming: the first contract did not ask "what moves the baseline, and when?" — the question whose answer later reversed the design. A fresh-context critique of the contract before workstream A was built would likely have found it; the operator found it instead, after the fact, which is what supervision is for but is the expensive way to find it.

**Harness leverage** was the branch's engine. Ten delegated agent runs, each with a written brief naming its files and forbidden files so two could run at once; agents never committed; Fable reviewed every diff and changed things in five of them — the diff pairing switched to newest-record-wins, CRLF normalised before hashing, references resolved against source folders, a report-level test added for the atomic fix, and the stamp's hash source moved from the previous record to the current report after the skills agent found the gap. A fresh agent ran the new `/memory-consolidate` skill as written on the repo's own ten logs, and its nine friction findings went straight back into the skill — the single best test a skill had on this branch. Seven pulses over three days; every landing pulsed.

**Verification & ownership** is the honest weakness, and it is the same weakness the consolidation retired to a ritual step on this very branch. Every artefact eyeball was Claude's: the `check --against` diff after a visible edit, the stale and dangling findings provoked on example 9, the hash equal to a fresh `sha1sum`, the record refusing example 8. The operator looked at none of it. Step 5a — the step that exists because this lesson recurred in four reflections — was asked at the close and answered "I'll do this on a live repository, on my mobile it's difficult". That is a better answer than the four silences before it: a reason and a stated intent, recorded here verbatim. Whether the step works is now a question with a date on it: the next reflection will say whether the live-repository look happened. Two operator decisions were taken at the close against Fable's recommendation and are recorded as decisions, not defects: the bump is **patch** to 2.1.1 although the branch adds a command, a folders key and two report keys (Fable proposed minor); and the security review was skipped, which Fable also recommended.

**Learning engagement** was real and specific: "you lost me", "what does the counter-suggestion mean for me", "should we have a linting skill for consistency down the road", "what have we learnt from the kiss skills that should go back into the branch skills". Each question opened the next piece of work. **Architecture sense-making**: the operator can explain the design — the ceremony is the only writer, the baseline moves once per closed piece of work — because they wrote that sentence themselves before Fable did.

**Where the sum beat the parts.** The operator's instinct ("leaner and sparser, based on pull requests, not builds") and Fable's diagnosis (the baseline moves on every build; dev builds churn the hashes) were two halves of one finding; neither had it alone. The skills agent, asked only to describe a contract, found that a close cannot stamp a note from the previous record's map — a gap the engine agent then closed by putting current hashes on the report. And the dogfood agent, asked to follow the skill literally, exposed nine ambiguities the skill's author could not see.

**Competency level: Agentic engineering lead, earned on this branch and not only by the workflow it ran inside.** Three reframing decisions that each changed the product, a delegation convention that held across ten agent runs, a skill dogfooded by a fresh agent before it shipped, and the lessons of eleven previous sessions folded into rules and ritual steps. The caveat is the same as the last four reflections' and now has a mechanism attached to it: no artefact was looked at by a human, and the step built to change that was deferred at its first asking, with a reason.
