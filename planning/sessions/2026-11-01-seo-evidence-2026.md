# Session — 2026-11-01: kiss-seo from the 2026 evidence, and a sitemap that only states known dates

## Intent (captured at /branch-open)

**Objective:** Bring `kiss-seo`, GUIDE's `llms.txt` framing and the sitemap's dates in line with what platform documentation and measurement support in November 2026, following the research report `planning/reviews/2026-11-01-seo-best-practices-2026.md` (notes beside it in `planning/reviews/2026-11-01-seo-research-notes/`), so that every kiss site stops publishing a build-time `lastmod` and an agent using the skill avoids the traps a model gets wrong.

**Success criteria:**

- [ ] **C1, sitemap:** `<lastmod>` is the page's `sitemapLastmod`, else its `updated`, else its `date` (page option first, then the resolved model, read as `.feed()` reads a date), else omitted; `<priority>` and `<changefreq>` are written only when the page sets them. A unit test for each case, each seen red against the old code. A fleet site's `sitemap.xml` is byte-identical across two builds.
- [ ] **C1, upgrade:** 2.9.0, with an upgrade note in `CHANGELOG.md` and in `kiss-site-migrate`; GUIDE § .sitemap(), `llms.txt`, `AIKB/sitemap.md`, the JSDoc and `types/` say the new rule, and the old "default: the current time" sentence is banned in a `CONTRADICTIONS` table.
- [ ] **C2:** GUIDE § .llms(), `AIKB/llms.md` and `src/models/guide.json` describe `llms.txt` and the Markdown copies as an index for agents and tools, with no claim that a search or answer engine reads them; the old sentence is banned in a `CONTRADICTIONS` table.
- [ ] **C3/C4 and cuts:** `kiss-seo` no longer carries the heading rule, the link-text line, the `og:image` line, the kiss-mechanics bullets other skills hold, or the review mode's re-listing of audit ids; it says `llms.txt` and `.md` copies serve agents, not search. `test/unit/skill-coverage.test.js` still passes, with rows moved rather than dropped where a cut line was the one a row pinned.
- [ ] **A1–A5 in `kiss-seo`, each with its date and source:** structured data types that still earn something (and the ones that do not, dated; no self-serving review stars; Course list needs three or more courses); area pages vs doorways (and no keywords in the profile name); search bots vs training tokens and the CDN edge; AI search is ordinary SEO; dates move only when content does. Author identity goes to `kiss-writing-for-the-web` as one line beside "never invent a fact".
- [ ] **Measured, with and without:** three targeted briefs on real fleet sites, old skill against new, fresh agents in sterilised copies (the 2026-10-31 harness, each copy's source commit recorded): course markup on a1k9training, "we also cover these towns" on pro-plumbing or k9-solutions, "stop AI companies scraping us" on one site. Results recorded in a review under `planning/reviews/`, with the arm counts stated as measured and anything else marked as inference.
- [ ] **Clean-room:** a fresh agent given only the packed tarball builds a small course site in an empty folder, reaches `kiss-ssg check` ok, and reports every place it had to guess; the sitemap it produces has no build-time `lastmod`.
- [ ] Gates green; the operator reads `kiss-seo` end to end on the PR (the 2026-10-30 log's ask).

**Non-goals / out of scope:** a git- or hash-derived `lastmod` (operator chose known-date-or-none); IndexNow or any deploy hook; an engine JSON-LD validator or the search-bot `Disallow` audit extension (named in the report as mechanism, deferred unless an arm shows the need); Google Business Profile advice beyond the profile-name trap; promoting the arm harness to `scripts/` (its own branch); the post-2.8.5 per-site review sessions; changes to sites' tracked files.

**Impact surface:** public API — what `.sitemap()` writes changes for every site on `^2` (no build-time `lastmod`, no default `priority`), so a minor, 2.9.0, with an upgrade note; the rest is docs and a shipped skill.

**Expected shape:** planned — the research report is the plan (C1–C4, cuts, A1–A5); the arms may add amendments.

- **2026-11-01 — `disallowAll` stops counting training-only tokens (operator: fix it here).** Found while writing A3: `disallowsEverything` (`lib/robots.js`) is true for a `Disallow: /` under any user agent, so blocking `GPTBot` to opt out of training logged "no crawler will index it" and set `report().robots.disallowAll` — a false alarm that would push an agent to undo the block A3 recommends. It now counts every block except an allow-list of tokens their vendors document as training-only (`GPTBot`, `ClaudeBot`, `Google-Extended`, `Applebot-Extended`); an agent not on the list still counts, so the alarm stays conservative. This narrows the non-goal "the search-bot `Disallow` audit extension": that extension (flagging a block on a known search bot) stays deferred.
- **2026-11-01 — the alarm asks whether search is blocked (operator: "count only `*` and known search bots"); replaces the design above.** The old-skill "stop AI scraping" arm blocked `CCBot`, `meta-externalagent` and `Bytespider` and had to tell the owner to ignore "no crawler will index it" on every build: an allow-list of training tokens was the wrong class, because the next unlisted bot hits the same false alarm. `disallowAll` is now `*` or a search engine's documented crawler; every named agent kept out of the whole site goes in a new `report().robots.blocked` and one `info` line. The operator then asked how a disallow rule got into the code base and that the default allow every bot: checked and answered — kiss's default is `User-agent: *` / `Allow: /` and no commit ever changed it; the only `Disallow` lines were in the scratchpad arm copies, written because the brief asked to block; every real site's tree is unchanged and allows all crawlers. `kiss-seo` now states allow-all as the default and forbids adding a block unasked.
- **2026-11-01 — two additions from the operator's "AI Impact on SEO Trends" report (operator: "Yes please. The goal of this branch is to build SEO optimisation best practices in to kiss").** The report's sources are SEO-vendor blogs; its FAQPage/HowTo, `Llms-Txt:` robots directive and "the model parses llms.txt" advice contradict platform documentation and were not taken. Taken, where Google's own docs agree: (1) `kiss-writing-for-the-web` — say what only this business can say, ask the owner for first-hand facts (Google: "original", "first-hand experience"; AI pipelines drop passages that repeat ones they hold); (2) `kiss-seo` — the hand-over names the off-site work only the owner can do (Business Profile, real reviews, directories and "best of" lists, consistent profiles), with a review check for pages a competitor could publish unchanged. Both to be measured by a with/without arm before the close.
- **2026-11-01 — the two additions kept against the recommendation, and `kiss-seo`'s review mode becomes a tick-box checklist.** The before/after pair on k9-solutions showed no measurable difference, and Claude recommended cutting both. The operator kept both. Reason, in the operator's words: "Your benchmarking against sites that already employ pretty good practise, so they're not the best test bench. I'd rather have a tick box list to ensure audits consider the key findings from the reports when evaluating (because we don't know the state of other kiss sites)." So the review mode's prose list is now `## Review checklist`: every key finding of the research as a box, each reported ticked, a finding, not applicable or not checked, never left out; a coverage row pins it (seen red against the previous skill).
