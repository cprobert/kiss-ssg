# Session — 2026-09-12: Broken links, server-side redirects, a feed, and a blog exemplar

## Intent (captured at /branch-open)

**Objective:** Give a kiss site two more verdicts an agent can act on — broken internal links, and pages removed without a server-side redirect — plus a feed derived from the same registry as the sitemap, and a blog exemplar that teaches pagination, tags, aliases and the feed by shape; so that after "what is this site", the next two management questions ("what did I break", "what did I lose") have machine answers.

Contract: `planning/plans/2026-09-12-link-check-redirects.md`.

**Success criteria:**

- [ ] **Links.** On a settled non-dev build the report carries `links: { checked, broken: [{ page, href }] }`, resolving root-relative and relative `href`/`src`/`srcset` against written files, output paths, directory indexes, extension-less pages and the asset manifest, ignoring schemes, protocol-relative, fragments and empties; check mode included; dev builds report `null`; `config.links = false` switches it off; `check --summary` prints `broken link:` lines; exit code unchanged.
- [ ] **Redirects.** A page's `aliases` write a byte-stable `<build>/_redirects` (`/old /new 301`); a recorded site reports pages present in `AIKB/last-build.json` and absent now with no alias covering them, and an alias that collides with a live page; both as `redirects.removed` / `redirects.collisions` with summary lines; no meta-refresh anywhere.
- [ ] **Feed.** `kiss.feed({ title, section?, limit?, filename?, dateField? })` writes valid RSS 2.0 from the registry, newest first, dated pages only, URLs identical to the sitemap's, byte-stable; requires `siteUrl`; replayed on a whole-site rebuild; `report().feed` names the file.
- [ ] **Exemplar.** Example 11 (a blog) builds clean with pagination, tag pages, one alias, a feed and a sitemap; `--broken` shows exactly one `broken link:`; its `AIKB/` is recorded and committed with two stamped notes; every recipe has a README; example counts say eleven everywhere; `npm run eg11`.
- [ ] Every new `lib/` module has its unit test and AIKB doc in the same commit; `llms.txt`, `README.md`, `CLAUDE.md` and `types/` updated; `npm run gates` green.

**Non-goals / out of scope:** meta-refresh redirects; `.htaccess`, `vercel.json` or nginx output; external link checking; an HTML parser dependency; a model schema language; any exit-code change for a finding; a version bump, CHANGELOG entry or PR before `/branch-close`.

**Impact surface:** public API — a new method (`.feed()`), a new page option (`aliases`), a new config key (`links`), three new report keys, a new example in the tarball. Obliges `llms.txt` + `README.md` + `types/`; the close should propose **minor** (the operator chose patch for the previous branch's additions and may again — say so at the bump).

**Expected shape:** planned — a written contract, an adversarial read of it before building, four workstreams in a fixed order.

**Delegation convention:** Fable briefs, reviews every diff and commits; sub-agents implement inside a named file scope and never commit. A fresh-context agent critiques the contract before the first workstream starts.

**Contract:** `planning/plans/2026-09-12-link-check-redirects.md`, amended in place with dated sections.

## Reflect — what the session was

**Planned, then planned again.** The branch opened from a menu: Fable had surveyed what other generators do well and the operator picked from it with opinions attached — "broken internal links checker is genius", "not very hot on meta refresh, I prefer server-side http code redirect", "I don't really understand feed() but I'm open to it". Those three sentences became the contract's non-goals (no meta-refresh, no `.htaccess`, no external checking) and its scope, and the contract went to a fresh-context agent for an adversarial read before a line was built. That read found nine blockers, the decisive one structural: the contract had placed the link scan at a step check mode never reaches, because `KISS_CHECK` discards staging before `_finishBuild`. The fix — extract references at write time, resolve once above `complete()`'s three-way branch — is the shape that shipped, and it is a better shape than the contract's.

The plan then bent once, deliberately and deep. Mid-branch the operator brought a pattern from their own CMS work: a link manager, so pages address each other by name and a move rewrites every link. Fable proposed deriving the name from the view route rather than inventing a registry; the operator agreed and asked for one thing to be watched — how the link verification just built would be affected. That produced a second contract amendment, a second adversarial read (six blockers, two of them exactly the interaction the operator had pointed at), and three more workstreams. It was recorded as an Amendment, absorbed on this branch, and it doubled the branch's public surface. Good drift: the identity work made example 11 honest (its pagination and tags now link by name), gave the `removed` finding a way to tell a moved page from a deleted one, and cost the link checker nothing — 171 references still resolve. The planned shape served this branch throughout; the contract-then-critique cadence held twice and paid twice.

## Evaluate — how the human supervised the AI

**Pushback & steering was the branch's sharpest instrument, and it fired twice at exactly the right moment.** The first steer was the one-line caveat on the identity ask — "pay close attention to how the link verification features we just wrote are affected". Fable would have briefed the helper as a rendering concern; the caveat made the interaction the critique's brief, and the critique found that `absolute=true` via `toAbsoluteUrl` would have emitted `/data/` for a page written as `data/index.json`, which the checker would then have reported as broken — a bug the helper and the checker would each have passed their own tests with. The second steer was the question near the end: "a key part of developing kiss is to ensure LLMs understand how to use kiss. what have you done to propagate this knowledge to kiss agents?" Fable's honest audit answer was: every shipped surface, and not the skills. `kiss-site-new` had zero mentions of `{{link}}`, `id`, `aliases` or `.feed()`. The engine had a mechanical net for every doc surface — `test/aikb.test.js` for the notes, the pack gate for `llms.txt`, types for the signatures — except the one an agent actually follows. Five skills were fixed and a test now holds them. Neither steer was absorbing a first answer; each changed what shipped.

**Problem framing** was strong in an unusual way: the operator framed by taste rather than by spec, and the taste was precise enough to become non-goals verbatim. "I prefer server-side http code redirect" is a complete architectural decision, and it kept a meta-refresh fallback out of the design without a debate. The gap in the framing was the criterion `config.links = false`, which the built shape does not honour — it is `config.links = { check: false }`, a block, because the critique argued a bare boolean would make the ignore list a real deploy wants a breaking rename later. Right call, recorded in the contract amendment, but the success criterion was never re-worded, and the Verdict below has to say so.

**Harness leverage** was the engine again, and it was better used than on the previous branch because the previous branch's lesson was applied. Two adversarial reads before building, fifteen blockers between them, all found from the contract alone. Seven delegated workstreams with named file ownership; two ran concurrently after a Beat 0 commit carved the shared seam so neither touched the other's files. Every agent proved its tests red in a `git archive` copy of HEAD rather than stashing a tree another agent was editing — a discipline the first pair invented and the rest inherited, now written into `AIKB/testing.md`. Fable changed something in most reviews (the single call site above the settle branch instead of the contract's three; `redirects` null on "no alias and no finding" so a recorded site's baseline does not churn between its first two records). Seven pulses, one per landing; no landing went unpulsed.

**Verification & ownership is the same honest weakness as the last five reflections, and this time it has less cover.** Fable's own eyeballs did real work — the `check --summary` run on example 11 found two defects 1192 passing tests had not: the helper's failure message leaked the staging folder path, and the `moved`/`removed` findings named output files while recommending an alias, which is a URL. Both fixed with tests. But they were Fable's eyes. Step 5a asked the operator to run one command and read one line, and the answer was "Can't look now", recorded as **unanswered — proceeding on the ritual's defaults**. Last close the deferral came with a reason and an intent ("I'll do this on a live repository"); this close it came with neither. The step is doing what it was built to do — making the absence visible — but two consecutive deferrals are the start of a pattern, and the real-site run it was deferred to has not yet happened either.

**Learning engagement**: "I don't really understand feed() but I'm open to it" is the right sentence to say to an agent — it got an explanation, a decision, and a feature the operator can now describe. **Architecture sense-making**: the identity design is the operator's own pattern; they can explain why a page has a name and why links follow it, because they brought the idea.

**Where the sum beat the parts.** The operator's CMS instinct (pages addressed by name) and Fable's constraint (derive it from the view, never a second registry) produced a feature neither described alone. The operator's "watch the link checker" and the critique agent's fresh read produced the `/data/` finding. And M's agent, asked only to pair renames by id, flagged that a `.html` site's operator pasting the recommended alias would not silence the finding — `coveredByAlias` accepting either spelling is that agent's catch, not the contract's.

**Competency level: Agentic engineering lead, on the strength of the workflow and its two steers.** A contract critiqued before building, twice; a delegation convention that ran seven workstreams with concurrent agents and no collisions; a question that exposed an untested doc surface and turned it into a permanent test.
