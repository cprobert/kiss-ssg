**Objective:** Give the v2 engine and its gate tooling the independent critical-friend review they never had before 2.0.0 is cut, hand every verified finding to the operator to triage, then implement what they choose on this same branch — plus a design spec, no code, for a watch-mode dependency graph.

**Success criteria:**

- [ ] Every `lib/` module and every `scripts/` module is covered by exactly one review lane (A lifecycle, B watch/replay, C paths, D helpers/contract, E gate tooling).
- [ ] Every finding carries a repro script or a named test that demonstrates it, or is explicitly labelled reasoning-only.

- [ ] The review report is committed to `planning/reviews/2026-09-05-v2-engine-review.md`.

**Non-goals / out of scope:** No engine changes during the review phase. No implementation of the dependency graph. No `/branch-close`, no PR, no publish. Skills and prose docs are not code-reviewed. Backfilling historical tags is the operator's task, outside this branch.

**Impact surface:** engine internals — the review touches nothing; the fixes will touch `lib/` and `scripts/` with the public API unchanged unless triage says otherwise, in which case this line is amended.

**Expected shape:** emergent — the findings decide the second half of the branch.

# Session Reflection — 2026-09-06: Independent review of the v2 engine, then everything that survived triage

_A Claude Code session is supervised collaboration: Claude generates, the human directs and judges. The session's quality is set by how actively the human supervised it. This reflection reads that supervision, as CPD for both._

**What we shipped:** 68 commits on `review/v2-critical-friend` (`abe1d96` … `60fcb41`, plus this close), 156 files, +9,575 / −1,215. A committed critical-friend review of the whole `lib/` and `scripts/` surface (44 findings, `planning/reviews/2026-09-05-v2-engine-review.md`), a watch-mode dependency-graph spec with its first two steps landed, every triaged finding fixed with a failing-first test, two real consumer sites migrated and built on the result, a gap analysis, a second triage round of eleven engine additions, and examples that an agent can run. Suite 447 tests across 32 files (from 170 at open); `lib/` coverage 95.5% statements. Version bumped to 2.0.0-alpha.2.

## Reflect — what the session was

The brief at `/branch-open` was deliberately two-phased and **emergent**: review first, with nothing changed on sight, then implement whatever the operator's triage kept. That shape held. The review phase ran as five parallel read-only lanes (four Opus agents, one in-context) plus a sixth addendum lane when the first pulse found two modules uncovered; the operator triaged the 44 findings in four decisions ("everything, including P3", "failures fail the build", "delete `folders.root`", "spec step 2 now"), and the implementation ran as three waves of one-item-at-a-time delegation. Then the branch kept earning its context: a livereload steer pulse produced W3-9; a close-out batch (examples theme, docs site, two consumer migrations, gap analysis) produced 27 more findings; a second triage of those, one AskUserQuestion per item, produced eleven engine additions; and a final conversation about agentic consumers produced the examples `--dev` change. Five dated Amendments record each expansion. The emergent shape served the work: every expansion came from evidence the previous phase generated, not from speculation, and each was absorbed on the open branch as the workflow prescribes rather than forked.

## Evaluate — how the human supervised the AI

**Problem framing** was the strongest dimension and set the whole session's quality. The operator did not ask for fixes; they asked for findings with verdicts, to be triaged by them. That one framing decision is why 44 findings became 42 fix-nows with no argument about scope later — the arguing happened up front, in four answers. The second triage repeated the pattern at finer grain: "one at a time, ask questions so we can tackle each" produced fourteen decisions, each with a recommended option and a stated alternative, and thirteen took the recommendation. The one that did not ("Yes, and add a seventh example") is the clearest example this session has of the sum beating the parts: Fable proposed documenting the multi-output pattern, the operator added the runnable example, and that example became the exemplar tier the agentic-enablement discussion later built on.

**Pushback & steering** showed up as steers rather than corrections, and at the right moments. "Is there anything needed to improve livereload compatibility?" arrived as a pulse question, not a feature request, and was answered with evidence (livereload's own README snippet versus kiss's hardcoded host) before the operator said "put that improvement in place". "This kiss site has a different approach that's well worth testing" added metacarpus as a second consumer with a shape the first did not have (versioned cohort outputs), and that consumer surfaced the `cleanBuild` archive question that became `cleanBuild: 'atomic'`. "Before we close the branch, should we consolidate some of the examples?" challenged the examples' one-idea-at-a-time design against the agent-reader it now serves; the answer kept the design and fixed the one thing that hurt an agent (the examples never exited). Each steer was small, timely and evidence-led.

**Harness leverage** was designed rather than reached for. The three-model delegation convention (Fable briefs and reviews every diff, Opus implements judgement work, Sonnet does mechanical work) was inherited from the v2 spec and applied to about forty agent runs; the three branch beats were all used, with eleven pulse entries; plan mode framed the review; a plan file carried the implementation across a context compaction. Two runtime failures were handled without losing work: an Opus session rate limit killed one agent before it touched the tree, and a background Explore agent was lost silently, which is why every later agent was told to write its findings to a file as it went. Fable wrote no implementation code on this branch, as the convention requires, and the one time an agent's report and the tree disagreed (a pulse line claiming a flake fix was verified when the loop had exited on a grep match) the pulse log was corrected in its own commit (`8e36fe8`) rather than left standing.

**Verification & ownership** is where intended and actual supervision diverged, and it should be said plainly. The operator intended to triage every finding and did. But the verification of every landed fix was Claude evaluating Claude: Fable re-ran the lane repro scripts against the fixed tree, reviewed each diff against the brief, and ran the suite, while the operator saw summaries and pulse lines. The examples redesign was "eyeballed" from screenshots by Fable, not by the human. The consumer migrations were built and probed by an agent and reported. None of this was hidden, and the failing-first discipline (every fix's test shown failing on the unfixed code, every deliberate flip named in its commit) gives the summaries teeth. But the human never opened a built page or a diff on this branch, and on a 9,500-line change that is a real gap between a summary trusted and a site looked at.

**Iteration discipline** was strong by cadence: eleven pulses, one per wave or batch, each with the suite count and the repro sweep, and the spec's status line flipped in the same commits. The two flakes found were root-caused (a test asserting mid-sweep; a write racing chokidar's initial scan) rather than padded, and one of those root causes widened `_replay()`'s try so a failed replay keeps the last good build, a behaviour the review had not asked for but the flake exposed.

**Learning engagement** and **architecture sense-making** are the thin dimensions. The operator asked one conceptual question all session ("should we convert to TypeScript, and would that force clients to?") and it was a good one, answered with a no and a reason. Otherwise the explaining ran one way: Fable explained each proposal's alternative in the AskUserQuestion, the operator chose. Whether the operator could brief someone on the serial rebuild queue, the atomic promotion, or why `json` is excluded from livereload's `extraExts` is not evidenced in this session; the AIKB docs and CHANGELOG carry the explanations, but they were written for the next reader, not read by this one.

**Competency level: Agentic engineering lead.** The evidence is the workflow, not the volume: a review-then-triage framing that kept the human's judgement at the decision points and out of the implementation; a delegation convention applied consistently across three models; five Amendments and eleven pulses that make the branch's expansion legible to a reader months from now; and the system being improved after failure (agents told to write findings to disk after one was lost; `node docs` made to exit after it hung a session; the examples made to exit after the same lesson repeated). The dimension that keeps this from being an unqualified reading is verification: the lead designed the checks but did not run them personally, and the reflection's job is to say so.
