# Session — 2026-10-02: Split `lib/kiss.js` down to the orchestrator, and the Windows ENOENT flake

## Intent (captured at /branch-open)

**Objective:** Bring `lib/kiss.js` (3,773 lines, ~64 methods) back under the one-job-per-module
rule by moving each non-orchestration responsibility into its own `lib/` module, without changing
anything a consuming site can observe; and find, fix and prove the cause of the Windows `ENOENT`
flake recorded in `AIKB/testing.md` (2026-10-02).

**Success criteria:**

- [ ] `lib/kiss.js` keeps the public methods and the build lifecycle (constructor,
      `page`/`pages`/`scan`, `generate`/`complete`, `_settle`/`_drain`, `sitemap`/`llms`/`feed`/`robots`,
      `watch`/`close` as entry points); staging and promote, report assembly (report inputs, links,
      audit, redirects, AIKB recording), page preparation and the id registry, and the watch/rebuild
      loop each live in their own `lib/` module. The line count left in `kiss.js` is measured and
      stated at the close (expected roughly 1,200–1,600), not asserted.
- [ ] Extracted code is shaped as **functions taking the `Kiss` instance**; `Kiss` keeps thin
      delegating methods, so private-field names and the instance's state stay on `Kiss`.
- [ ] Every new module has a `test/unit/` sibling, an `AIKB/` doc and a row in the `CLAUDE.md`
      table, in the same commit as the extraction; `test/unit/aikb.test.js` passes. `AIKB/kiss.md`
      is rewritten to describe the orchestrator and point at the new docs.
- [ ] No public behaviour moves: `types/` regenerated by `npm run types` shows no change to the
      `Kiss` public surface (diff of `types/kiss.d.ts` reviewed — only new module declarations, if
      any); `llms.txt`/`README.md` need no edit; every example builds byte-identical `public/`
      before and after (`npm run eg1`…`eg12`, diffed), example 8 still exits 1.
- [ ] One seam per commit, with `npm test` green between each — a bisectable series, not one move.
- [ ] Flake: a load harness reproduces the `ENOENT` on this Windows machine **before** the fix; the
      root cause is named from what it showed; after the fix the same harness runs clean and the
      full suite passes 5 consecutive runs. If it cannot be reproduced, the branch says so and
      `AIKB/testing.md` is updated instead of shipping a speculative fix.
- [ ] `npm run gates` green, and a non-Claude review (Codex) of the `lib/` diff at the close.

**Non-goals / out of scope:** No public API, config or `BuildReport` shape changes; no behaviour
fixes discovered during the move (each is recorded as an Amendment and decided by the operator,
not folded silently into a "pure move" commit); no collaborator classes / state moved off `Kiss`;
no splitting of other large `lib/` modules; no `/memory-consolidate` (recommended separately).

**Impact surface:** engine internals — the API is unchanged; obliges an `AIKB/` doc, unit test and
`CLAUDE.md` row per new module, and a patch bump.

**Expected shape:** planned — the seams are visible in the method list, and the contract maps
which methods go where before any code moves.

**Delegation convention:** the main session writes the contract and does every extraction itself,
one seam per commit. One fresh-context agent critiques the contract adversarially before any code
moves (what does each moved function read and write on `kiss`, and which seam's state does another
seam touch?). Agents never commit.

**Contract:** `planning/plans/2026-10-02-split-kiss-orchestrator.md` — written and critiqued before
the first extraction; amended in place with dated sections.

**Inherited feedback (read back at open):** "after the first review finding, fix the class / the
promised semantic, not the case" now appears in three logs (2026-10-01, 2026-10-02 ×2) —
`/memory-consolidate` recommended between branches. For this branch it means: when one seam turns
out to leak state, check every seam for the same leak before the next commit.
