# Session Reflection — 2026-09-30: The docs site, rebuilt on kiss and deployed to Pages

_A Claude Code session is supervised collaboration: Claude generates, the human directs and judges. The session's quality is set by how actively the human supervised it. This reflection reads that supervision, as CPD for both._

**What we shipped:** the docs site as a kiss-built, multi-page site for GitHub Pages under `/kiss-ssg/` (`6c12f9e`). Its guide pages are cut from `GUIDE.md` by `src/controllers/guide.js`, the operator's logo and a palette taken from it replace Bootstrap (`9ee619a`), and every external link opens in a new tab (`058d192`). Two shipped changes rode along: a `kiss-site-review` step for that rule (`118fdbf`), and an engine fix to `lib/watcher.js` for a dev-server rebuild loop (`d8e7ba6`). Version 2.6.6 (`83d0d32`).

## Reflect — what the session was

**Emergent, and it said so.** It started as "make GitHub Pages serve the kiss site", a one-file workflow fix. It became a nav fix and an agent-first section, then a design review, a full redesign with a page split, a logo, a review-skill rule and an engine fix. ## Evaluate — how the human supervised the AI

**Pushback & steering was the strongest dimension.** The operator corrected the sites list with facts Claude could not have had (drop two sites, add K9 Solutions). They added a design rule of their own, that external links open in a new tab, and had it go into the shipped skill rather than only this site. They chose the engine fix over a workaround when the choice was put to them. And they asked the right sceptical question at the right moment: "I'm concerned about the Dev loop. Is that really fixed?". That question tried to buy an independent check twice through `/codex:review`. Neither attempt ran: the first because the command takes no focus text, the second because the machine ran low on memory. The attempt was right; the harness let it down.

**Verification & ownership was the weakest, and the gap is on both sides.**

- **The human's eyeball never happened.** It was a success criterion from the open, it was asked for four times, and it was answered "Not now" at the close.
- **The only independent review did not run.** Codex hit its usage limit, and the operator chose to proceed. The engine change's evidence is therefore two red-first tests and one measured dev run, both Claude's.
- **Claude's own visual checks were unreliable for most of the session.** Screenshots of scrolled pages timed out, and Claude attributed that to the browser tool for about eight attempts before finding the real cause. `node docs` reports its path without `.js`, so the watcher treated the `docs/` build folder as the build script and rebuilt forever. Claude had looked at the dev log once, early, and read "no rebuilds" from a moment before the loop started. Some later timeouts, with the preview idle, were genuinely the tool, which made the story harder to see.

**Iteration discipline was low.** The 45-file redesign landed as one commit with no pulse, and the branch was never pulsed at all. Claude named the pulse as due twice and did not offer to run it.

**Harness leverage was good in reach, uneven in follow-through.** The operator reached for:

- the `frontend-design` skill, for the review and plan;
- `/branch-open`, late;
- `kiss-site-review`, run as the product's own skill against its own site;
- Codex, twice.

Claude used the browser, `kiss-ssg check`, the coverage row and the red-first discipline. The late branch-open and the never-run pulse are the misses.

**One process slip, Claude's.** A commit was chained to `npm run gates | tail`, so it ran after a failing gates run. The failure was the format gate choking on two just-deleted files. The gates passed on a re-run, so the commit stands, but it is the exact chaining failure `CLAUDE.md` § Git workflow warns about.

**Intended versus actual supervision.** The operator intended to check the result: the eyeball was their criterion, and the Codex review their idea. What actually closed the loop was Claude's measurements. The branch reaches its PR with no human look at a built page and no independent review.

**Competency level: Assisted operator**, at the edge of Active supervisor.

- **For Active supervisor:** the steering and framing decisions were sharp and consequential, and the operator turned a one-off preference into a shipped rule.
- **Against it:** both of the checks that would have made the result owned rather than reported, the eyeball and the review, did not happen.

## Feedback — recommendations for next session

- **Operator — open the branch before the work, not after it.** Here the first `/branch-open` came after a full redesign existed on `main`. Next time "can you update X" grows past one file, run `/branch-open` there, so the criteria shape the work instead of describing it.
- **Operator — take the eyeball when it is asked for mid-branch, not at the close.** It was this branch's own criterion, and "Not now" at the close means nobody has looked at the site below the fold. Five minutes with `node docs --dev` after the redesign commit would have done it.
- **Claude — when a tool keeps failing against something you are running, check the thing you are running first.** Eight screenshot timeouts were blamed on the browser tool while `node docs --dev` rebuilt in a loop. On the second timeout, read the process's log again, not only once at the start, and before concluding "tool quirk".
- **Claude — never chain an action after `| tail`.** Capture the command's own exit code (`cmd > log; echo $?`) and gate the next step on it. The `CLAUDE.md` rule already says to chain with `&&`; a pipe to `tail` silently replaces the exit code the `&&` was guarding.
- **Claude — offer the pulse, don't just name it.** "`/branch-pulse` is due" appeared twice in replies and never became a pulse. Say "run a pulse now?" as a question when a slice lands.
- **Process — `scripts/gates.mjs`'s format gate fails on an uncommitted deletion.** It hands prettier a deleted path. Have it filter the changed files to those that exist.
- **Process — an independent review that depends on one metered account is not a gate.** Codex was the only independent reviewer, and it was unavailable at the close. When `lib/` changes, run the review at the slice (or pulse) that changed it, while there is time to wait out a limit.
