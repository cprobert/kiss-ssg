kiss-ssg is a static site generator for Node, built to be driven by a coding agent. The agent writes plain Handlebars, JSON and a little JavaScript, and every build ends in a verdict it can act on.

npx kiss-ssg@latest init
Read the guide

How it works

  1. Set it up

    One command installs kiss-ssg, adds a starter site, and points your agent at the API contract. Then add the two Claude Code plugins it prints.

    npx kiss-ssg@latest init

  2. Describe the site

    Open Claude Code and say what the site is for, who it's for, where it will be hosted and its address. The skills do the rest.

    claude

  3. Check the build

    A dry run that reports every page, broken link and missing launch detail as data, and publishes nothing. Exit 0 means it's right.

    npx kiss-ssg check router.js

The full setup, including the two Claude Code plugins, is in the README quick start. Using another agent? Point it at node_modules/kiss-ssg/llms.txt and have it run the check.

Why it suits agents

  • Conventions, not questions

    Folders, routes, helpers and asset names all have defaults, so an agent has fewer choices to get wrong, and every default can be overridden.

  • A verdict, not a log

    A failed page or a link to a page that doesn't exist fails the build. Mistakes can't ship quietly.

  • Readable by the next person

    Handlebars views, JSON models and small controllers. Whoever opens the site in two years can follow what the agent wrote.

  • A memory of the site

    npx kiss-ssg aikb records what the site is, so the next session starts from facts rather than guesses.
