# embed.js

## Responsibility

Click-to-load embeds: what `{{embed}}` writes. A frame from another site (a video, a map, a post) waits in a `<template>` behind a notice until the visitor asks for it, so nothing is fetched or stored before a click. The site decides the mode, never the template:

- **under `config.consent`**, the embed is one of the site's declared services. Its notice offers **Load it** and **Always allow**, and `lib/consent-client.js` reveals it when the stored choice allows it and records it for withdrawal;
- **with no `config.consent`**, the service is the preset alone and the embed is a facade: a **Load it** button, a link to the provider, and a small script written after it that wires the button. Nothing is stored, so there is no choice to remember and nothing for a banner to ask.

It exists because of the 2026-11-04 clean room (`planning/reviews/2026-11-04-embed-clean-room.md`). An agent asked to add a YouTube video to a site with no banner found the consent helper, read that one video needs no banner, and hand-built 32 lines of facade instead.

## Public interface

- **`embedService(name, consent)` → `ConsentService`.** Under `config.consent`, the site's declared service of that name. **Throws** for an undeclared one, naming `config.consent.services` (an embed the config does not know would be missing from the banner and the cookie table). With `consent` null, `presetService(name)` from `lib/consent.js`. **Throws** for a name with no embed preset, listing the ones there are.
- **`embedMarkup(name, service, { consent, text, params, src, title })` → `string`.**
  - **Under `config.consent`:** `div.kiss-embed[data-kiss-embed][data-kiss-consent]`, a `[data-kiss-consent-ui]` notice with **Load it** and **Always allow** (`data-kiss-consent-action="load"|"allow"`). A `necessary` service gets the plain iframe.
  - **Without it:** `div.kiss-embed[data-kiss-embed][data-kiss-embed-facade]`, a `[data-kiss-embed-ui]` notice with one **Load it** (`data-kiss-embed-action="load"`), and `facadeScript()` after the box.
  - **Both:** the box carries the frame's geometry inline (below). The wording is `text` (the site's `ui.text`, or `DEFAULT_TEXT`), filled in one pass: `{provider}` with the provider and `{service}` with the label. The provider's own link (`embed.watch`) is the notice's last paragraph, so it hides with the notice; it is omitted when there is none or a placeholder cannot be filled. The iframe sits inside `<template data-kiss-embed-frame>`, sized inline (below), and followed by `measureScript()` when `embed.measure` is set.
  - **Throws** with no title, no src, a `{param}` with no value, or a frame src or filled `embed.watch` that `isHttpUrl` refuses (below).
- **`isHttpUrl(value)` → `boolean`.** Whether a URL is safe to frame or link: `new URL(value, 'https://kiss.invalid/')` resolves, and its protocol is `http:` or `https:`. Not a string, or a value the parser refuses, is `false`.
- **`facadeScript()` → `string`.** `kissEmbedFacade`, inlined by its source. It finds its box through `document.currentScript.previousElementSibling`, so an embed works wherever it is put with nothing in `<head>`. On a click it puts the template's frame in place, hides the notice and focuses the frame.
- **`measureScript(frameSrc)` → `string`.** `kissEmbedMeasure`, for a frame that reports its height. It listens for `{"type":"MEASURE","details":{"height":N}}` from the frame's own origin and sets the height of the iframe whose window sent it. Empty for a src with no origin. `embedMarkup` calls it only after `isHttpUrl` has passed the src.
- **`embedPresetNames()` → `string[]`.** The presets with an `embed`, in preset order.

## Non-obvious behavior

- **Every frame URL must resolve to http(s)** (security hardening, 2026-11-06). The frame has no `sandbox`, so a `javascript:` src runs in the page's origin, and a call-site `src=` from model data (`{{embed "google-maps" src=model.map}}`) was written into `<iframe src>` with attribute escaping alone. `isHttpUrl` checks three values: the call-site `src=`, the filled `embed.src`, and the filled `embed.watch`. It is an allow-list of two schemes decided by the URL algorithm, so leading whitespace, a tab inside the scheme, any case, `data:`, `vbscript:` and `blob:` are refused without being listed; a root-relative path, a bare relative path and a `//host/…` URL pass, because a browser resolves them to the page's own scheme. Where each check sits is load-bearing:
  - **after `fill`**, because a `{placeholder}` in a template's host position does not parse until it is filled. A placeholder cannot bring a scheme in: `fill` URL-encodes `:`, so `{id}` as `javascript:alert(1)` fills to the relative path `javascript%3Aalert(1)`;
  - **before the bare iframe** a `necessary` service returns;
  - **outside the `try` around `embed.watch`'s `fill`**: a watch link with a placeholder that has no value is still left out, but one that fills to another scheme throws rather than silently disappearing.

  A refusal throws `embed "<name>": the frame's src "<url>" is not an http(s) URL — …` (or `embed.watch "<url>"`), which the `embed` helper turns into a failed page in a build and a warning with no markup in dev (`consentFail`); `test/unit/embed.test.js` drives the real helper both ways. The value written is the author's string, not the parsed URL, so a valid embed's markup is unchanged. Not checked here: whether the frame's origin is one of the service's declared `origins` (content, not script execution, and it would change what a site may embed), and a `{{consentScript … src=}}` URL (`AIKB/consent-gate.md`). A service's `policy` keeps its own stricter rule in `lib/consent.js` (`policyUrl`: absolute http(s) only, because a relative path is wrong for another site's policy).

- **The size is on the iframe, not in the theme.** A 16:9 player and Instagram's frame need different CSS, and that is a property of the provider's frame, not the site's look. So `style` carries `display:block;width:100%;border:0`, then either `aspect-ratio:<ratio>;height:auto` or `aspect-ratio:auto;height:<height>px`, and `max-width:<width>px;margin:0 auto` when the preset caps the width. The consent theme's `.kiss-embed iframe` rule was removed with this module. A site that wants another size overrides it with `!important`, or with its own `ratio`, `width` and `height` under `config.consent`.
- **The Load button's words and name.** The words are, in order: one call's `own.load`, else `text.embedPlay` for a `video` service, else `text.embedLoad`. They are filled like every other word (`{provider}`, `{service}`). Its `aria-label` is `<words>: <frame title>`, words first so the name contains what is shown (WCAG 2.5.3 label in name), which tells a screen-reader user which of several embeds a button loads. `own.notice` and `own.open` replace the notice and the watch link's words the same way. `text` is the consent manager's `ui.text`, else the site's `embeds.text`, else `DEFAULT_TEXT`: the helper decides which, so `embedMarkup` never reads config.
- **`resolveEmbeds(input, consent)` → `{ text }|null`**, for `config.embeds` (`lib/config.js`). It is the wording of a site with no `config.consent`, under the same four keys `ui.text` uses (`EMBED_TEXT_KEYS`: `embedNotice`, `embedLoad`, `embedPlay`, `embedWatch`; not `embedAllow`, which only the consent manager offers). It throws on `embeds` beside an active `consent`, so there is one home for the words and no precedence rule to learn. "Active" is the **resolved** consent: `lib/config.js` calls it after `resolveConsent`, so `consent: false` (switched off) takes `embeds`. Until Codex's slice-4 review it read the raw input and refused `false`. It also throws on any key other than `text`, on an unknown wording key, and on a value that is not a string.
- **Autoplay is asked for by the click, never written into the frame.** A `video` service's box carries `data-kiss-embed-autoplay` unless the call said `autoplay=false`. The facade's click handler, and the consent client's `load` action (`AIKB/consent-client.md`), set `autoplay=1` on the cloned iframe's `src` before inserting it. The `<template>`'s own `src` never has it, because the consent client also reveals a frame from a stored choice, with no click, and that must not start a video. Measured in headless Chromium 156 with a real YouTube video (2026-11-05, `aqz-KE-bpKQ`): playing unmuted at 6.4 s, eight seconds after the click; the `autoplay=false` control paused at 0. iOS Safari is not measured.
- **A poster (`poster`, markup the helper already wrote with the `{{image}}` pipeline) is the one case where kiss writes colour** (the operator, 2026-11-05). The 2026-11-04 geometry-only rule assumed a plain box. Text on a photo is unreadable without a backing, so the operator chose a readable default over geometry only. With a poster, the box gains the class `kiss-embed--poster` and `position:relative;justify-content:flex-end`. The still is a `.kiss-embed__poster` wrapper, absolute at `inset:0`, carrying the same `data-kiss-embed-ui` / `data-kiss-consent-ui` attribute as the notice, so both reveal paths hide it with no client change. The notice becomes a compact full-width strip: padded, `.875em`, tight paragraph margins, and the watch link beside the button rather than under it. This came from the operator's look at `/branch-close` (2026-11-05). On an unstyled site at 375 px the first strip covered 69% of the box with its text against the edges; the compact one covers 44% at 375 px (52% at 320, 9% at 1440), with the text 12 px in. The browser suite holds it under 50% at 375 px and under 15% at 1440, and was red without it. It is all inline, because a `<style>` per embed would be the CSS audit's `inline-style-repeated`, so no media query is possible. Its colours are **custom properties with fallbacks** (`--kiss-embed-poster-scrim`, `--kiss-embed-poster-text`), because a site cannot beat an inline style without `!important` but can set a variable. The notice's paragraphs and the watch link get `color:inherit` inline. That beats any rule on them: the consent theme's `.kiss-embed__notice p` is muted, which measured `color(srgb .3 .3 .3)` on the strip in Chromium (Codex, slice 3), and a site's own link colour (a1k9training's is `text-brand-700`) would be as bad. The browser suite checks every `p` and `a` in the strip, in the facade and under the consent theme. A service whose `embed.video` is set (youtube, vimeo) gets `PLAY_MARK` on its Load button: an `aria-hidden` SVG, not `▶`, which iOS draws as a colour emoji. Without a poster the markup is byte-identical to before.
- **The Load button carries its words in `data-kiss-embed-label`**, in both the facade and the consent box (2026-11-08, #78's reporter). a1k9training's poster restyle sets the button's text node to `font-size:0` and redraws a backed label with `::after { content: 'Play video' }`, because a bare text node cannot carry a backing, and a `load=` change would silently disagree with that CSS. With the attribute, a site writes `content: attr(data-kiss-embed-label)`. The words are escaped as an attribute. Measured in Chromium against `embedMarkup`'s own output: `::after` shows the words, `load=` changes them with no CSS edit, and the accessible name (`aria-label`) is unchanged. Placed after `aria-label`, on every embed, poster or not.
- **The box holds the frame's space, so a video's frame loads without moving the page** (the operator, 2026-11-04, after the after-run's screenshot showed a bare paragraph, button and link). The box's inline style is geometry only: a centred flex column, `box-sizing:content-box`, the frame's `aspect-ratio` (or `min-height` of its starting height), and the same width cap. No colour or border, so the site's CSS or the consent theme decides the look. `content-box` because the ratio is the frame's: a site's `* { box-sizing: border-box }` would take the theme's padding out of it and the loaded frame would push the box taller. A box with more text than room grows, since an aspect ratio gives way to its content (a narrow phone with the consent notice's two buttons). The browser suite measures it: at 320 px the box is 16:9 before the click and the same height after, and the next embed does not move. For a measured frame, `kissEmbedMeasure` clears the box's `min-height` when it sets the reported height, so an Instagram box does move once: measured on the real reel `DfQCqMnhpsG` through `{{embed}}` (2026-11-04), 288 × 600 → 288 × 568 at 320 px wide, and 540 × 600 → 540 × 883 at 1440. The height is about the width × 1.25 + 208 px for a 4:5 post (both measurements fit it), which CSS cannot express on the box without a container query; left as the 600 px estimate.
- **Instagram reports its height without `embed.js`.** Measured on 2026-11-04: a plain `/p/{id}/embed` frame posts `MEASURE` (568 px at 320 wide, 883 px at 1440), and `/p/{id}` serves a reel as well as a post. The listener checks `e.origin` and matches `e.source` against each iframe's `contentWindow`, so another frame's message cannot resize anything. It is written once per measuring embed, so two Instagram embeds add two listeners, each of which sizes only the frame that spoke.
- **The wiring check ignores a facade.** `consentWiringProblems` (`lib/consent-gate.js`) counts a `data-kiss-embed` box as gated markup that needs a consent head, unless it carries `data-kiss-embed-facade`.
- **The audit reads a facade like a consent embed.** `lib/audit.js` takes the frame's origin from the template and marks it with the service, so `thirdParty` lists it, and neither `consent-missing` nor `consent-ungated` reports it.
- **On a learning package's page `{{embed}}` is always the facade**, even under `config.consent`: the helper passes `consent: null` to `embedMarkup` when the page names a `package`. The LMS deals with consent there (2026-11-03), because a consent reload would break the learner's SCORM session and a `Path=/` cookie would be shared by every course on the LMS's domain. A facade stores nothing and never reloads, so neither applies (the operator, 2026-11-04). Until then it failed the page in both modes. The service is still looked up through `embedService` with the site's consent, so a consent site still declares it and its wording is the site's. Inferred, not measured: an LMS that serves packages under a CSP without the provider in `frame-src` will refuse the frame once Load is pressed; GUIDE says to test it in the LMS.
- **The wording without `config.consent` is the default `ui.text`.** A site that needs other words declares the service under `config.consent`, which also brings the banner. Known limit, not decided: a site with no banner cannot change the facade's words.
