# utils.js

## Responsibility

Small string/path helpers shared across the engine: slugification, title-casing, path sanitization, URL normalisation, content hashing, and the engine's one file-globbing entry point.

## Public interface

- `trimLines(lines)` → `lines` with every line `.trim()`ed and rejoined with `\n` (trailing newline added).
- `toSlug(slug)` → NFKD-normalised, combining marks stripped, lowercased, every run of anything outside `[a-z0-9]` collapsed to a single `-`, leading/trailing `-` trimmed; if that leaves nothing, `'p-' + sha1(input).slice(0, 8)` (an empty/whitespace-only input stays `''`).
- `toTitleCase(str)` → each space-separated word capitalized.
- `trimPath(path)` → leading/trailing `/` stripped.
- `sanitizePath(path)` → `trimPath`, split on `/`, each segment passed through `toSlug`, rejoined with `/`; returns the input unchanged (including falsy) if falsy.
- `posixPath(path)` → backslashes converted to `/` and a leading `./` stripped.
- `globFiles(dir, pattern)` → every file matching `pattern` under `dir`, each through `posixPath`, sorted. `dir` is a literal directory (glob-escaped), `pattern` is the glob. The engine's only glob call site.
- `toURLKey(value)` → the page-identity key for a URL or build path: leading and trailing `/` stripped, the last segment's file extension dropped, a trailing `index` segment removed. The home page is `''`. Identity only — nothing emitted is built from it.
- `toCanonicalPath(pageURL)` → the same path with the last segment's file extension removed and nothing else touched (`courses/index.html` → `courses/index`, `courses/bronze.html` → `courses/bronze`). What `canonical` and `sitemap.js` hand `toAbsoluteUrl`.
- `toAbsoluteUrl(siteUrl, urlPath)` → `siteUrl` (trailing slashes trimmed) joined to `urlPath` (leading slashes stripped, repeated slashes collapsed, a trailing `index` segment — with or without an extension — replaced by a trailing `/`) by exactly one `/`. An explicit trailing `/` is **preserved**; a bare path stays bare; a file extension is kept. An empty path gives `siteUrl` with a single trailing slash.
- `servedPathFor(pageURL)` → the root-relative path a static host serves that page at: `/` + the page's build-relative URL, with a trailing `index.html` collapsed to a trailing `/` (`index.html` → `/`, `about.html` → `/about.html`, `about/index.html` → `/about/`, `courses/index.html` → `/courses/`, `data/index.json` → `/data/index.json`). The one derivation behind `{{link}}`.
- `relativePathFor(fromPageURL, toPageURL)` → one page's file as a reference from another's (`tab-2.html`, `../l2/index.html`; a page linking itself gets its own file name). No policy and no collapse: it names the file, because it is `{{link}}`'s href on a learning-package page, which an LMS serves file by file from wherever it unpacks it, and a folder link is exactly what an LMS does not resolve. Not a fifth URL policy beside the four below: it carries no host and no site-wide shape at all.
- `hashId(input)` → MD5 hex digest of `input` if it's a string, else of `JSON.stringify(input)`.
- `redactUrl(url)` → a URL as kiss **shows** it, never as it fetches it: scheme, host, port and path kept (as the WHATWG parser writes them: host lowercased, a default port dropped), no `user:pass@`, no fragment, each query parameter's name kept and its value replaced by `[redacted]` (`?access_token=SECRET&type=course` → `?access_token=[redacted]&type=[redacted]`: kiss cannot know which value is the secret, and the names are what tell one model from another), a parameter with no `=` replaced whole (`?[redacted]`), an empty query dropped. A secret in the **path** cannot be told from a path segment and is shown as written; `GUIDE.md` § Remote models sends a credential to `fetch.headers`. A string the parser rejects, **or one it accepts with a scheme that is not `http:` or `https:`** (the parser gives such a scheme no authority, so `httpx:user:pass@host/x` parses with the credentials as its path, and was shown whole until 2026-11-06), cannot be split into credentials, path and query (a password may hold a raw `/`, `?`, `#` or `@`), so it goes by the position of its **last** `@` against its first `?` or `#`: no `@`, it is cut at the first `?` or `#` and given `?[redacted]` when it had a query; the last `@` before that cut, everything between the scheme and that `@` is dropped and then the same cut applies (`https://user:abc/def==@api.example.com/data?x=1` → `https://api.example.com/data?[redacted]`); the last `@` after it, only the scheme is kept (`https://user:pa?ss@api.example.com/data` → `https://[redacted]`). "The scheme" is `scheme:` with whatever run of `/` or `\` follows it, as written, because the parser opens an authority after `http:`, `http:/` and `http:\\` alike; a string with no scheme keeps nothing before its `@`. **Named export only, not on the default object** — it is engine-internal, and the default object is the public `utils` a site imports.
- `REDACTED` → the string `'[redacted]'`, the one word every redacted value becomes: `redactUrl`'s query values and `lib/config.js`'s `redactFetchHeaders`. Named export only, not on the default object.
- `isUrlModel(model)` → `true` for a string whose scheme is `http:` or `https:`, in any case and after any leading space (`/^\s*https?:/i`, both of which `fetch` takes), `false` for anything else, a non-string included. The one test of whether a page's `model` is a URL kiss fetches, made by `lib/model-resolver.js` (`resolveModel`, which fetches it), `lib/aikb.js` (`classifyModel`, which records it) and `lib/page-registry.js` (`registerPage`'s `No view specified` log, which redacts it). Until `b8be845` it was the prefix test those three copies made (`startsWith('http')`), which had two faults the code review of that commit named: `HTTPS://api.example.com/x?token=…` and a URL with a leading space were taken for a folder, never fetched, and printed whole by `Invalid model …`, past every redaction; and `httpdata.json`, a file, was sent to the network. `httpx://…` is not a URL model either: it is a string `resolveModel` rejects, shown through `redactUrl`. Named export only, not on the default object.
- `escapeXml(value)` → `String(value)` with `&` (first, so the entities after it are not re-escaped), `<`, `>`, `"` and `'` replaced by their entities: right for XML text and for an attribute value alike. Moved here from `lib/feed.js`; used by `lib/feed.js`, `lib/sitemap.js` and `lib/package-manifest.js` (whose private copy was removed 2026-11-11). Named export only, not on the default object.
- `escapeRegExp(text)` → `text` with every character a `RegExp` reads specially escaped, for building a pattern from a path or a name. Named export only, not on the default object. Used by `lib/css-purge.js`, `lib/staging.js` and `lib/issue.js`; `lib/audit.js` and `lib/links.js` still carry older copies of their own (recorded 2026-11-08, not merged).
- `export default { trimLines, toSlug, toTitleCase, trimPath, sanitizePath, posixPath, globFiles, hashId, toURLKey, toAbsoluteUrl, toCanonicalPath, servedPathFor, relativePathFor }` (also each function is a named export).

## Non-obvious behavior

- `toSlug` is the whole naming contract for a page's output path (`slug`, each `path` segment, and the `ext`), so it has to be both **stable** and **collision-free per distinct input**. The algorithm: `normalize('NFKD')` splits an accented letter into base letter + combining mark, `\p{M}` strips the marks (so `'Über uns'` → `'uber-uns'` rather than `'-ber-uns'`), everything outside `[a-z0-9]` collapses to `-`, and leading/trailing dashes are trimmed (`'  --hello--  '` → `'hello'`; `toSlug('foo!')` → `'foo'`, where it used to leave a trailing dash).
- **The hash fallback is what stops non-Latin titles colliding.** A script with no Latin decomposition — CJK, Hangul, Cyrillic — leaves nothing after the strip, and the old `[\W_]+` rule slugged _every_ such title to `'-'`: a multilingual `.pages()` fan-out built one file and the rest were dropped by the duplicate-`buildTo` check (review finding C6). Empty results therefore fall back to `'p-' + sha1(original).slice(0, 8)` — short, stable across builds, prefixed so it still reads as a slug. It is deliberately _not_ a transliteration: it is unique and reproducible, not readable. A truly empty input still returns `''`, so `sanitizePath` keeps its behaviour on an empty segment (`'a//b'`).
- Transliteration means two titles that differ only by accent (`'Über uns'` and `'Uber uns'`) now share a slug. That is a genuine collision and `Kiss._preparePage` fails the build on it, rather than one page silently overwriting or losing the other.
- `hashId` hashes objects by `JSON.stringify(input)`, not by their `toString()` — this fixes a v1 bug where `md5(object)` implicitly called `.toString()` on the object first, hashing the literal string `"[object Object]"` for _every_ object regardless of content (so all object-model pages collided on the same id in v1).

- `globFiles` exists because glob v9+ changed two behaviours the engine relied on: it strips a leading `./` from the paths it returns (while every `config.folders.*` default carries one, so a caller slicing the folder prefix off a result would slice the wrong number of characters), and it no longer sorts results — walk order would make page order, partial registration order and sitemap order depend on the machine. Routing every glob through here fixes both once. Do not call `globSync` directly from another module.

- **The directory is taken separately from the pattern so it can be escaped** (`escape()` from `glob`). A project path is a literal name, not a pattern: a folder called `site[old]` interpolated straight into a pattern is read as a character class and matches nothing, so `scan()` found zero pages and Sass compiled nothing while the build still reported success (review finding A-07). Callers therefore pass `globFiles(folder, '**/*.hbs')`, never a pre-joined string — joining it yourself puts the folder back inside the pattern and reopens the bug.

- **`toCanonicalPath` and `toAbsoluteUrl` live here because two modules need them, not because they are string helpers.** `lib/sitemap.js` builds every `<loc>` with them and `lib/handlebars-helpers.js` builds `{{canonical}}` with them, so a page's canonical URL and its sitemap entry are produced by one pair of functions and cannot disagree (review gap O5). Putting the join in either caller would have made the other import a module whose job is something else.
- **A directory index's trailing slash is the host's policy, and `config.links.trailingSlash` is where a site states it.** Measured live on 2026-09-16, not remembered:

| Host                                                                    | Directory index | File page           |
| ----------------------------------------------------------------------- | --------------- | ------------------- |
| Netlify (`www.a1k9training.co.uk`)                                      | `/courses/` 200 | `/x` 200, `/x/` 301 |
| Firebase Hosting, `cleanUrls` + `trailingSlash: false` (`learna.ac.uk`) | `/courses` 200  | `/x` 200, `/x/` 301 |

They agree on file pages and contradict each other on directory indexes, so one has to be the default and the other has to be sayable. The default stays Netlify's (`trailingSlash: true`): all 18 `<loc>` entries in a1k9training's live sitemap return 200 under it, and moving it would turn six of them into redirects. **GitHub Pages' file pages are measured** — `/about` and `/about.html` both 200, `/about/` 404s and nothing redirects (relayed from a clean-room session's live deployment, not measured here; the table in `GUIDE.md` § Host URL policy carries the same row) — but a **real directory index** on it is still unverified, which is the half that decides the policy. Cloudflare Pages and bare nginx are unverified outright — check before claiming either way rather than reasoning from the three host names this doc used to list. `toAbsoluteUrl` and `servedPathFor` each take the policy as an option and **must be given the same one**: the first is every absolute URL kiss emits for a page (the one exception is `llms.txt`'s link to a page's Markdown copy, which names a file, `courses/index.md`, and is joined as one — the policy would turn it back into `courses/`; `AIKB/llms.md`), the second is `{{link}}`'s href, and a site that splits them links `/courses/` while canonicalising `/courses` — taking the redirect the setting exists to avoid on every internal click. The site root is the one URL both conventions agree on: its whole path is the `index` segment, so either replacement empties it and the join returns `${siteUrl}/`.

- **A directory index canonicalises with a trailing slash by default, and that is the whole point of `toAbsoluteUrl` keeping one.** `courses/index.html` is served by Netlify at `/courses/`; that host answers the bare `/courses` with a 301, and Google's guidance is that a canonical must be the URL that returns 200. `toAbsoluteUrl` therefore replaces a trailing `index(.ext)?` segment with an empty last segment (`courses/index.html` → `courses/`) instead of dropping it, and no longer trims a trailing slash it was given — `{{absUrl '/courses/'}}` is `https://site/courses/` while the bare `{{absUrl '/courses'}}` stays `https://site/courses`. Repeated slashes are collapsed on the way through. The defect this fixes was found on a real site (`a1k9training`), which was regex-patching its own sitemap after every build.
- **`servedPathFor` is the fourth, and it is the only one that describes what the _host_ does.** The other three are about the URL a site _advertises_; this one is the path the file is actually fetched from, which is what an in-page `href` needs: `about.html` is served at `/about.html`, not at the pretty `/about`, unless the site is extension-less (where the two coincide). Two rules make it distinct. It collapses **only `index.html`**, never another `index.<ext>` — `toAbsoluteUrl`'s `index(\.[^./]*)?` strips any extension, which would advertise an `ext: 'json'` index page at `/data/`, a directory with no `index.html` in it, and `lib/links.js` would rightly call that broken. And it is **root-relative, always**: a link to a page is a path from the site root, and the absolute form is a separate, explicit ask (`{{link … absolute=true}}`, which string-joins `siteUrl`'s origin and prefix to this) rather than something the derivation guesses. Its output is a path `resolveReference` accepts by construction — file, `<dir>/`, or `/` — which is what keeps `{{link}}` and the link checker from ever disagreeing (`AIKB/links.md`).
- The three URL functions are **three, not one, and the differences matter**: `toURLKey` is page _identity_ — it drops the extension _and_ the trailing `index`, so `/courses`, `courses/` and `courses/index.html` are one key, which is what `isActive` compares, is deliberately unchanged by the trailing-slash fix, and **takes no `trailingSlash` option at all**: a nav highlight must not depend on where the site is deployed, and "unifying the three URL functions" is how that breaks; `toCanonicalPath` drops only the extension, leaving the `index` in place; `toAbsoluteUrl` keeps whatever extension it is handed — an asset URL passed to `{{absUrl "css/site.css"}}` has to survive — and turns that surviving `index` into the trailing slash. Canonicalising through `toURLKey` is exactly what produced the redirecting URL, so do not put it back.

## Types

Every exported function carries `@param`/`@returns` JSDoc, because the default export is what `import { utils } from 'kiss-ssg'` hands a consumer — `types/utils.d.ts` is generated from it. Regenerate with `npm run types` after any signature or JSDoc change; `test/unit/types.test.js` byte-compares. `toSlug`, `toURLKey`, `toCanonicalPath` and `hashId` take `unknown` rather than `string`: each stringifies its argument itself, and narrowing the declaration would refuse calls the runtime handles.

- `isInside(directory)` returns a whole-segment containment predicate with resolved paths and platform case semantics. Config validation, watcher exclusions and Kiss event dispatch share it; it is a named export. Depends on `node:path`.

- Containment tests live in `test/unit/utils.test.js`; watcher no longer re-exports `isInside`.
