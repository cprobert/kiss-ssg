# links.js

## Responsibility

The broken-internal-link finding: given the references each page wrote and the folder it wrote them into, say which of them resolve to nothing. Four pure functions plus one default that touches the disk (`fs.existsSync`, injectable) — the module holds no state, knows nothing about `Kiss`, and decides nothing about when it runs.

The finding is **advisory**. It never moves `ok`, never moves an exit code, and never fails a page. It is a thing the build knows and a person cannot see.

## Public interface

- `extractReferences(html)` → `string[]`, sorted and deduplicated. Every `href`, `src`, `srcset` candidate and `action` carried by an opening `<a|link|script|img|source|video|audio|iframe|form>` tag, exactly as written. Empties, bare `#fragment`s and the `data:`/`javascript:`/`mailto:`/`tel:` schemes are dropped here — none of them can name a file the build wrote. Called by `KissPage.generate()` on the minified HTML, beside the `hash` assignment.
- `classifyReference(ref, { siteUrl })` → `{ kind: 'external' | 'internal', path: string|null }`. Strips the query and the fragment; an absolute URL whose **origin equals `siteUrl`'s** is internal (with `siteUrl`'s path prefix stripped too); any other scheme, and a protocol-relative `//host/x`, is external; anything else is internal with `path` kept as written. `path` is `null` for everything external.
- `resolveReference(ref, { pageBuildTo, buildDir, extensionLess, exists, known })` → `boolean`. Resolves root-relative against `buildDir` and relative against the page's own directory, `..` included, then accepts the path itself, `<path>/index.html` for a trailing slash, `<path>.html` or `<path>/index.html` for an extension-less path — each either on disk (`exists`) or in `known`. A path that escapes the build folder is always broken.
- `checkLinks({ pages, buildDir, siteUrl, extensionLess, manifestTargets, exists })` → `{ checked, broken: [{ page, href }] }`. `pages` is `[{ buildTo, links }]` for the pages that actually wrote bytes; `known` is built inside, from those `buildTo`s (made build-relative) plus `manifestTargets`. `checked` counts every reference classified internal; `broken` is sorted by page, then href, and records the href exactly as the page wrote it.
- The `LinkPage` typedef (`{ buildTo, links }`).

## Depends on

`node:fs` (`existsSync`, only as the default `exists`), `node:path` (`path.posix`, for resolution that behaves the same on Windows), `./utils.js` (`posixPath`). Nothing else — no HTML parser, no logger, no config.

## Depended on by

`lib/kiss-page.js` (`extractReferences`, at write time, parking the result on `KissPage.links`) and `lib/kiss.js` (`checkLinks`, from `Kiss._checkLinks()` in `complete()`'s settle path, latched on `_links` and handed to `buildReport` as the report's `links` key — `AIKB/build-report.md`).

## Non-obvious behavior

- **Extraction and resolution are split across time on purpose.** The references are pulled out of the HTML at write time and the file is never read back, because under `kiss-ssg check` — the command the finding exists to serve — the whole staging folder is deleted before anything could read it, and a scan that read pages back would have reported `checked: 0, broken: []` in silence. The cost is a few hundred bytes a page rather than the ~15 MB of retained HTML a 500-page site would need if the documents were kept. `AIKB/kiss.md` has the ordering half of this.
- **A same-origin absolute URL is internal, and that is the whole point.** `{{canonical}}` emits `https://site.example/courses/` on every page and `{{absUrl}}` emits one wherever a template asks; a rule of "ignore anything with a scheme" would skip exactly the OG tag and nav link a slug rename silently breaks. The origin test is `new URL(...).origin`, so a trailing slash on `config.siteUrl` is tolerated, and a path prefix (`https://example.com/docs`) is stripped as well: under that prefix the build folder is `/docs`'s root. A same-origin URL **outside** the prefix is called external — it is served by something this build did not write, so this build cannot say whether it is broken.
- **The asset manifest contributes its values, never its keys.** `{{asset 'css/site.css'}}` returns the emitted name, which under `assets.hash` is `css/site.a1b2c3d4.css` — and `recordEmitted` _moves_ the file, so `css/site.css` is not on disk at all. Accepting the manifest key would make a template that hardcoded `/css/site.css` pass while the browser 404s. With no hashing policy key and value are equal, so nothing is lost. An empty manifest (`folders.assets: null`, the deliberate shape of `examples/7-versioned-outputs.js`) is "no assets", not an error.
- **`known` is checked before the filesystem, and holds only pages that wrote bytes.** It is the cheap half, and on a page-heavy site most references are to other pages. It is built from the pages the scan was given — those whose `hash !== null` — so a link to a page with `generate: false`, or to one that failed to render, is reported as broken, which is the honest answer: no such file was published.
- **Everything else in the build folder is answered by the filesystem, which is why `Kiss` runs the scan where it does.** `sitemap.xml`, `llms.txt`, a feed, `_redirects` and anything a pipeline step wrote straight into the build are not pages and not assets; they resolve because they are on disk at the moment the scan runs. That is the reason the scan sits in `complete()`'s settle path rather than in `_finishBuild()`.
- **The extractor is one tolerant regex pass, not a parser, and it fails in the safe direction.** `<tag([^>]*)>` means an attribute value containing a literal `>` ends the tag early and the rest of it is not scanned — a reference _missed_, never a reference _invented_, which is the right way round for an advisory finding. Three deliberate refinements sit on top of it: inline `<script>` and `<style>` **bodies** are removed first (keeping the `<script>` opening tag, so `<script src>` is still seen), because a string inside JavaScript that reads `src="/x"` is not a reference — and because the dev livereload snippet builds its URL in code rather than in an attribute; HTML comments are removed, since a browser fetches nothing from them; and each attribute is anchored on preceding whitespace rather than `\b`, or `src` would also match the `src` inside `data-src` (`-` is a non-word character, so `\b` sits between them).
- **`srcset` candidates are split on `,` and then on whitespace.** A naive split on commas alone yields `img@2x.jpg 2x` as a URL, which resolves to nothing — so every responsive image in the site would be reported broken. `src` cannot be confused with `srcset` because the character after the name must be `=`.
- **A small, deliberate entity subset is decoded** — `&amp;`, the five named ones, and numeric `&#…;`/`&#x…;` — because that is what Handlebars emits into a query string. Anything exotic is left as written: an undecoded entity resolves to nothing and is reported, which is a visible wrong answer rather than a silent one.
- **`extensionLess` orders the two extension-less fallbacks and nothing else.** Both `<path>.html` and `<path>/index.html` are always tried, whatever the flag says: a site can mix the two shapes (a `.pages()` fan-out under `extensionLess` beside a hand-written `index` page), and accepting only the configured shape would report a real file as missing.
- **Both outputs are sorted**, the extractor's list and `checkLinks`'s `broken`. Two builds of the same site must produce the same report — the report is a JSON Lines record a diff is taken against.
