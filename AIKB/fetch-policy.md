# fetch-policy.js

## Responsibility

Applies `config.fetch` — headers, timeout, retries and an on-disk cache — to a single URL model request, and hands back the parsed body. Everything the engine does between "here is a URL" and "here is JSON" lives here; `model-resolver.js` keeps only the dispatch on model shape.

## Public interface

- `async fetchModel(url, { fetchImpl = globalThis.fetch, logger, headers, timeout, retries, cache })` → `Promise<data>` — the parsed JSON body of a 2xx response. Every policy key is optional and falls back to `DEFAULT_FETCH` from `config.js`, so a caller that passes only `fetchImpl`/`logger` gets today's behaviour plus the default timeout. Rejects with a fresh `Error` (no `cause`, no own properties) on a non-2xx response, a network failure, a 2xx body that is not JSON, a timeout or a failed cache write, whose message kiss writes from parts that cannot carry a secret (below), and on a header the fetch would refuse, whose message names the header and never its value (below).

## Depends on

`fs-extra`; `node:http` (`STATUS_CODES`); `./utils.js` (`hashId`, `posixPath`, `redactUrl`); `./config.js` (`DEFAULT_FETCH`).

## Depended on by

`lib/model-resolver.js`.

## Non-obvious behavior

- **A header the fetch would refuse is refused first, by name.** Node's `fetch` quotes a header value in the error it raises for one it cannot send (`Headers.append: "<value>" is an invalid header value.`), and `GUIDE.md` tells a site to put its token in `fetch.headers`: a token with a line break or a NUL in it, as a value read from a file can have, was printed twice by the failed-model log line (the review of `7c527a3`, 2026-11-06; measured on Node 24.14.0 through a whole build). The message is kiss's own now in any case (below), but refusing first also keeps the value out of anything Node might print on the way. So `checkHeaders(headers)` runs after the cache read and before the first attempt: it builds the same `Headers` the fetch would, and on a refusal throws kiss's own error, `fetch.headers: "Authorization" cannot be sent — … The value is not shown.`, naming each refused header of a plain record and nothing of what it holds (any other shape is refused without a name). It is outside the attempt loop, so it is never retried and the fetch is never called. `Headers` and the fetch's `Request` refuse the same inputs (measured on Node 24.14.0 for `null`, a record, pairs, a `Headers`, a `Map`, a bad name and a string), so no header set that worked is refused; a value that only ends in a line break is trimmed by both and still sent. A character above 255 is refused by Node with a message that does not quote the value; it gets kiss's message too. `test/unit/fetch-policy.test.js` drives it with the real `fetch`, counted.
- **Order of operations: cache read → header check → fetch (headers + timeout) → non-2xx guard → retry decision → parse → cache write.** The cache is consulted before anything else, so a cached model costs no network at all; the body is written only after a 2xx response has parsed, so an error envelope can never become a cache entry (the guard that `model-resolver.js` gained for the same reason — review finding C2 — stays authoritative over the cache). The cache write is outside the attempt's `catch`: a disk that refuses it fails the model once, as `Model cache write failed: <cache file> → <code>` (the file is the hashed name, never the URL), and is not retried, since fetching again cannot make the disk accept it. Before 2026-11-06 it was retried like a network failure and printed the `fs` error's own text.
- **The cache key is a hash of the URL _and_ the header set**, with the header entries sorted so key order cannot fork the identity. The same URL fetched with two different bearer tokens is two different identities upstream, and one build's body must never be served to the other's request.
- **The cache has no TTL and no expiry sweep.** A consumer clears the directory (or a single `<hash>.json` inside it) to refetch. That also makes stale-on-error unreachable rather than merely unimplemented: an entry is only ever written after a success, and once written it is hit before any request is made, so there is no state in which a fetch fails _and_ a cached body exists. Stale-on-error only becomes a real option if a TTL is added — which is why `cache` is a plain directory string, not a `{ dir, staleOnError }` object.
- **An unreadable cache entry is a miss, not a failure**: a truncated or hand-edited file logs one warning and the request goes to the network. A half-written file (a build killed mid-write) must not poison every later build.
- **The timeout is a `Promise.race` as well as an `AbortController.abort()`.** The abort is what a real `fetch` needs; the race is what makes the timeout hold for a `fetchImpl` that ignores its signal — the injected seam is a test stub or a polyfill as often as it is Node's `fetch`, and one that hangs would otherwise hang the whole build with nothing to report. The losing attempt gets a no-op `.catch()` so the abort's own rejection is never unhandled.
- **A 4xx is never retried, a 5xx and a network error are.** A 4xx is the server rejecting _this_ request — repeating it cannot change the answer, and hammering an auth failure can get a key locked. Backoff is linear (`200ms × attempts`), deliberately short: this is a build, not a daemon.
- **The attempt count is named in the rejection only when more than one attempt was made** (`… (after 3 attempts)`). With the default `retries: 0` the message is the single attempt's message as it is.
- **The URL is fetched as written and printed redacted.** Every message this module builds names the URL through `redactUrl` (`lib/utils.js`): no `user:pass@`, no fragment, each query value `[redacted]` — `Model fetch timed out after 20ms: <shown>`, `Model fetch failed: <shown> → 404 Not Found`, and `logger.debug('Model cache hit', <shown>)`. The query string is where an access token sits, and these messages land on stderr, in CI logs and in pasted bug reports; before 2026-11-06 all three carried it (measured). The request, the cache key and the resolver's `{ id }` keep the real URL.
- **No text from outside kiss reaches a failure's message.** Not an error's `message`, not its cause's, not the response's `statusText`, not the body. Node's `fetch` quotes the URL in its own errors (`Failed to parse URL from <url>`, `Request cannot be constructed from a URL that includes credentials: <url>`) and again in the cause's `input`; a server writes its status text and body (`403 Bad key <token>`, `Unexpected token 'S', "<token>" is not valid JSON` from `response.json()`); an injected `fetchImpl` can throw anything. Until 2026-11-06 a `scrubbed()` step edited that text to take the URL's spellings out, and each of three reviews found a shape it missed: a `localhost` failure whose `AggregateError` cause has an empty message (printed as a bare `fetch failed`), kiss's own timeout message put through a second redaction (`https://api.example.com//`, `?[redacted][redacted][redacted][redacted]`), and an error quoting a raw query the parser re-encodes (`?q=sec ret`). It was replaced, not patched: `failureOf()` decides the failure from facts kiss has (did a 2xx response arrive, does the URL parse, does it hold credentials) and never from an error's text, and writes `Model fetch failed: <redactUrl(url)> → <what>` from these parts only:
  - a non-2xx: `response.status` and its standard phrase from `node:http`'s `STATUS_CODES` (`403 Forbidden`, whatever the server's own status text said);
  - a network failure: the cause's (or, for a fetch with no cause, the error's own) `code`, `address`, `port` and `hostname`, each only when it is a finite number or a string of `[A-Za-z0-9_.:-]` (`ECONNREFUSED 127.0.0.1:62059`, `ENOTFOUND no-such-host.invalid`). That is a check of shape, not of value: it stops a URL or a sentence, and a token has the same alphabet, so a replaced `fetch` that put one in an error's `code` would have it shown (measured in the code review of `b8be845`: `code: 'sk-live-ABC123.def_456'` is printed). Node's own fetch puts only its constants there; an IPv6 address is bracketed so its colons are not read as the port's. An `AggregateError` cause (`localhost`, which is `::1` and `127.0.0.1`) gives each entry of its `errors`, comma-separated: `ECONNREFUSED [::1]:51942, ECONNREFUSED 127.0.0.1:51942`;
  - a cause message only when it is exactly one of `CONSTANT_CAUSES`, `redirect count exceeded` (a redirect loop), `other side closed` (a dropped socket, shown with its code: `other side closed (UND_ERR_SOCKET)`), `bad port` (a port fetch refuses to use, such as 1 or 6000) and `unknown scheme` (a model that begins `http` and is not `http:` or `https:`, such as `httpx://…`). These are the four constant cause messages measured on Node 24.14.0 that say something the code and address cannot; exact equality cannot carry a secret. **A cause that is not on the list and has no code is shown as the error's name alone** (`→ TypeError`): the last two were found that way, in a whole-build run after the list was first written, and the next one will look the same until it is measured and added. The other cause messages measured there either carried an address, a port or a host name (`connect ECONNREFUSED 127.0.0.1:<port>`, `getaddrinfo ENOTFOUND <host>`) and are said from those parts instead, were empty (the `AggregateError`), or belong to a failure kiss names from its own facts (`Invalid URL`, the cause of `Failed to parse URL from <url>`);
  - a 2xx whose `response.json()` threw a `SyntaxError`: `200, but the body is not JSON (text/html)`, the media type only when it is `type/subtype` in `[\w.+-]` after its parameters are cut; any other error from `json()` is the body failing to arrive, `200, but the body could not be read: <code>`;
  - a URL `URL.canParse` refuses: `not a URL that can be fetched`; a URL with `user:pass@`: `the URL holds a user name or password, which fetch will not send: put the credential in fetch.headers`;
  - otherwise the error's `name` when it is one word of letters (`Error`, `TypeError`), else `an error kiss cannot describe`.

  An error this module built itself (the timeout, a non-2xx) is kept in a `WeakSet` and passed on as it is, never rebuilt. Measured on Node 24.14.0 (2026-11-06) through the real `fetch` against a local server, with a token in the query, the status text, the body and the password: a closed port on `127.0.0.1` and on `localhost`, an unknown host, a dropped socket, a redirect loop, 401, 403 with its own status text, 500, 500 retried, an HTML body, a body that is the token, a media type that is not one, a real timeout, two unparseable URLs and a URL with credentials. No token reached a message, a stack or a logger call. `test/unit/fetch-policy.test.js` holds each shape, through the real `fetch` where it can be made locally and through a stub shaped as Node's errors were measured where it cannot (an unknown host, the `AggregateError` on a machine whose `localhost` has one address).
