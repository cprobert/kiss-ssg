# html-split.js

## Responsibility

Cuts a single-file HTML document into a kiss layout, a page view and one partial per region. Pure — no fs, no config, no logger, no knowledge of `Kiss`. The caller decides where the files go.

The mechanical half of converting a single-file site. The stylesheet is not this module's: it is copied in whole as plain `.css`, which kiss serves unchanged. (A stylesheet splitter, `lib/css-split.js`, shipped on this branch and was removed before 2.7.0 was published, 2026-10-02 — SCSS reads plain CSS differently in more places than a translation could keep up with, and the operator judged the split not worth it.) The division of labour is the point: parsing and cutting are things a person should never do by hand, and deciding that a region is called `hero` is not. Names are an input.

**What it deliberately does not produce is the model.** The precedent's `src/models/index.json` has `hero: { kicker, heading, intro, primary, secondary, image }` — semantic field names chosen by whoever did the conversion. A module that guessed at those would emit names no human would have picked, and nothing could check them. The structural cut is mechanical; lifting words into JSON is not.

## Public interface

- `parseHtml(src)` → `HtmlNode[]`, every source byte in exactly one node. Also re-exported from `lib/kiss.js`.
- `serializeNodes(nodes, depth)` → HTML, with a line break only where the source had one — it never adds whitespace.
- `attr(node, name)` → one attribute's value, as the tokenizer read it.
- `findTag(nodes, tag)` → the first matching descendant, breadth-first, or `null`. Also re-exported.
- `suggestName(node)` → a kebab-case name from `id`, else the first class, else the tag.
- `regionKind(node)` → `'chrome'` or `'section'`.
- `findRegions(nodes)` → `{ regions, wrappedInMain, container, main, body }`. Each region carries `kind`, `tag`, `name` and `node`. `container` and `main` are returned rather than left to be re-derived: `splitDocument` has to walk the same stream and unwrap the same element, and computing them twice is exactly how a `<script>` inside `<main>` got deleted.
- `bodyNodesOf(nodes)` → the nodes standing in for the body's children, falling through `<html>` when there is no `<body>` (it is optional and the tokenizer does not imply one).
- `nameRegions(regions, names)` → the regions with caller names applied and made unique.
- `findExpressions(nodes)` → every `{{…}}` the document carries, as short excerpts.
- `splitDocument(html, { names, layoutName, pageName, escapeExpressions })` → `{ layout, page, partials, assets, regions, expressions, warnings, stats }`. Also re-exported from `lib/kiss.js`. `warnings` is empty for every ordinary document; non-empty means the conversion did something it could not do losslessly and is saying so. `assets.scripts` is `{ attrs, type, content }` per src-less inline script, collected from the whole document. It throws only if its own output would carry a live expression, which is a bug in the module rather than a property of the input (see the backstop below).
- The `HtmlNode`, `HtmlRegion` and `HtmlSplitResult` typedefs. An `HtmlNode` element carries `open` and `close` — its tags as the source spelled them — and `attribs`.

## Depends on

`htmlparser2` (runtime dependency, added 2026-10-02) for tokenizing — see `AIKB/upstream.md`. Nothing else: no `node:` builtins, no other module of kiss's.

## Depended on by

`lib/kiss.js`, for the re-export only. Nothing in the build pipeline calls it; it is a tool a conversion reaches for, not a step a build runs.

## Non-obvious behavior

- **THE INVARIANT: assembling the layout, the partials and the page view through Handlebars reproduces the document that was split.** `test/unit/html-split.test.js` proves it on named shapes by rendering through `handlebars-layouts`, the way `lib/kiss.js` does, and **`test/unit/html-split.corpus.test.js` proves it on every pair of thirty-odd awkward atoms** — touching, a space apart and a line apart, at body level, in `<main>` and in a section — checking that whitespace-sensitive elements come back byte for byte and that nowhere else gains or loses whitespace.

  It has **three stated exceptions**, and stating them is the point. A qualified invariant is worth more than an absolute one that is wrong, and the module reports two of the three at the point they occur:
  1. `escapeExpressions: false` on a document containing `{{…}}`. Those braces are compiled rather than reproduced. Not reported — it is what the caller asked for.
  2. `{{` with a backslash already in front of it. Handlebars has exactly one escape, `\{{`, and a preceding backslash eats it; measured across runs of 0–5, two or more emit N−1 and evaluate anyway. So the braces go out as `&#123;&#123;` — the page renders the same, the bytes do not, and inside `<script>` or `<style>` neither does the text. In `warnings`.
  3. A node written **between two sections** — a `<nav>`, a `<script>`, a comment, stray text — is emitted after all of them. See below. In `warnings`.

- **The corpus is how this module is reviewed now, and why it exists.** Five review rounds (two security, three Codex) each found the next place the split changed a page, one adjacency at a time. The corpus stopped that: on its first run it found a bug in the very rewrite it was written to check (a stray close tag landing outside its parent). A finding becomes an atom in `ATOMS`, not a one-off test — a one-off test proves the case that prompted it and nothing beside it, which is the "fix verified only on its own input" failure the second security round named.

- **The tokenizer is htmlparser2, and the tree is made of source slices.** Until 2026-10-02 this was a hand-rolled scanner, and roughly half of what the reviews found was that scanner reading HTML differently from a browser: a `<` before a non-letter parsed as a tag, `/>` honoured on an HTML element (`<script src="a.js" />` then lost its real `</script>` and a browser read the rest of the page as script), an apostrophe in an unquoted value opening a quote, a raw-text element ended at `"</scriptfoo"` in a JS string, attributes read by a regex that matched `class='site-header'` written inside another attribute's value. htmlparser2 reads all of those as the spec does, and — unlike parse5 — never adds `<html>`, `<body>` or `<tbody>` the page did not write. Two choices make the tree lossless whatever it decides:
  1. **Every tag is kept as the source text that spelled it** (`open`, `close`) and printed from there. Quoting, attribute order, case (`<linearGradient>` inside `<svg>`), a trailing `/` on `<meta … />`, an odd close tag — all the source's own bytes, never re-serialised. A void element, an element self-closed inside `<svg>`, or one closed by a later tag or the end of the document has an empty `close`, so no close tag is invented.
  2. **Source the tokenizer reports nothing for is kept as text.** It drops malformed input silently — `</ x>`, a stray `</span>`, a trailing unfinished `<b` — so every gap between two events is filled from the source. Each byte belongs to exactly one node, by construction. The fill happens **before** a closing element is popped; after, it put a stray `</span>` outside the element it sat in.

  The tokenizer runs with tag names lower-cased: with case kept, it stopped recognising `<IMG>` as void and nested a `<P>` inside it. The spelling survives in `open`/`close`.

- **The escape, and the backstop behind it.** `{{` is escaped as `\{{` by default, everywhere — text, tags (names included), comments, raw text. What this module emits is `.hbs`, which kiss compiles, so braces in a foreign document are code: unescaped, an Alpine or Vue page has every interpolation evaluated to empty, and the same mechanism was measured carrying a config dump, a secret in a tracking pixel's query string and a file read from outside the site into a published page. `escapeExpressions: false` opts out; `result.expressions` reports what was found either way. Every review round found another surface the escape had missed — the container tags, the doctype, a backslash, a tag name — so **`assertInert` checks the output itself**: with the module's own `{{> …}}` and `{{#block …}}` removed, any `{{` without exactly one backslash before it throws. The next missed surface is an error, not an injection; confirmed by running a copy of the module with the tag-name escape removed. Adjacent text is also merged as it is read, so the escape sees the braces the output will have.

- **THE PRINTER NEVER ADDS WHITESPACE — the operator's call (2026-10-01).** Whether whitespace between two elements renders depends on their CSS `display`, which the markup cannot say: an inline-block `<li>`, two `<input>`s, two `<svg>`s. Each earlier rule rested on a list of inline elements, and each review found a member missing. Now a line break is written only where the source had a gap containing one — reshaped to this module's indent, which renders the same — a gap of plain spaces is kept exactly, and tags the source wrote touching stay touching. **The cost is legibility on minified input**, which is not re-indented at all: the structure is still cut, but a partial from a minified page is dense, and formatting it is the caller's deliberate, separate step.

- **A brace or backslash touching a region could become template syntax**, and the writer guards it (Codex round 6). Source text ending in `{` before a call or the content block made `{{{`, a `}` after one made `}}}`, and a backslash run escaped the call. A backslash run gets one more backslash (Handlebars emits N−1 of N ≥ 2 and still evaluates, so the page gets the source's run back exactly); a brace becomes its character reference, `&#123;` or `&#125;`, and the escape's own `\{{` before a call becomes `&#123;&#123;`. Only body-level text can touch a region, and there a reference renders the same — the bytes differ by that character, the one place they do outside the stated exceptions. The corpus carries `{`, `}`, `{{`, `}}`, `\` and `\\` as atoms; `{{` beside a region is what showed the escape case.

- **The rule holds across region boundaries too — `LineWriter`.** A region becomes a partial call, and the layout's chrome calls, the content block and the page view's section calls all go through a `LineWriter` that carries the source's gaps between them: a gap between two sections goes into the page view between their calls; before the first and after the last it stays in the layout. Handlebars makes this harder than it looks, because a partial call **alone on a line** is "standalone" (`AIKB/upstream.md`): it indents every line of the partial by the call's indentation, and it swallows its own line's newline. So a call that starts a line is written at column 0, a line break after a call is written twice, and a source line break that arrives inside a text node rather than as a gap of its own gets the same treatment. Partial files carry no trailing newline, so a call adds exactly the region's bytes. Codex measured the boundary case before this existed: two `display:inline-block` sections came back with a newline between them.

- **Regions are an allowlist of default-block elements** (`BLOCK_REGION`: `section`, `div`, `header`, `ul`, `p`, …). Inline, replaced and custom elements and assets — `script`, `style`, `template`, `noscript` — are never regions and stay in the layout where they were written; a top-level `<style>` once became `sections/style.hbs`.

- **Inside an element whose whitespace renders, even a gap is content.** `<pre>`, `<listing>`, `<xmp>`, `<plaintext>`, SVG's `<text>`, `<tspan>` and `<textPath>`, and any element whose inline `style` sets `white-space` (or `white-space-collapse`) to a preserving value are emitted verbatim. **The stated limit:** a class whose stylesheet sets `white-space: pre` cannot be seen from the markup, so such an element is treated like any other. A `<main>` that preserves whitespace is not unwrapped (below); a `<body>` that does is reported in `warnings`, because the layout's own line breaks would render there.

- **One walk handles `<html>`, `<head>` and `<body>` at whatever level the document wrote them**, because all three are optional. Reaching for them by name and emitting a skeleton deleted everything they sat beside — an SRI `<script>` after `</body>`, a build marker between `</head>` and `<body>` — first inside `<html>`, then again in a document with no `<html>`. `<html>` is never added to a document that did not write it; only a bare fragment gets the skeleton.

- **The layout is rebuilt by walking the body in document order**, not by emitting chrome-before, the content block, then chrome-after. That positional shape re-emitted a bootstrap `<script>` last, deleted a `<script integrity=…>` inside `<main>` outright, and ignored comments between sections. Body `<script>` tags therefore sit in the layout where they were written, ahead of the per-page `{{#block "scripts"}}`.

- **A node between two sections is MOVED, not dropped — a documented limitation.** Sections render at a single `{{#block "main"}}`, so `<section>A</section><nav>N</nav><section>B</section>` assembles as A, B, N. Keeping the order would mean the page view emitting the interleaved run, making a `<nav>` between sections page-scoped rather than shared furniture; the operator judged that a bigger change to every converted site's shape than the defect earns (2026-10-01). `warnings` names each node moved, scripts included — they are where a move changes behaviour.

- **`<main>` is unwrapped only when there is exactly one, every section is inside it, and its whitespace does not render.** A page wrapped in `<main>` would otherwise have one region; the layout keeps `<main>`'s own tags around the content block. With a section beside it, unwrapping moved sections across the boundary (Codex, 2026-10-01) — a different landmark and a different `main > section` — so then `<main>` stays whole as one region. `<main>` is never added to a page that did not have one.

- **Inline `<style>` and `<script>` are reported, not removed.** `assets.styles` and `assets.scripts` say what is worth lifting; the document keeps them. Removing them broke the invariant silently — the live round trip against `k9solutions.uk` lost both `<script src>` tags. Lifting means choosing a filename and rewriting the tag, which only the caller can do. Each comes with its `attrs` (and a script with its lower-cased `type`), because the attributes decide what the text is: a `module`, JSON-LD or an import map is not lifted as a classic script, and a `<style media="print">` merged into one unconditional stylesheet applied print rules on screen (Codex, 2026-10-02). The rule the skill and example 12 follow is the one that cannot reorder the cascade: lift the styles only when none carries an attribute, and otherwise lift none.

- **Two regions can propose the same suffixed name, and the uniquifier loops.** `hero`, `hero`, `hero-2` once gave two regions `hero-2`: one filename, two partials, one region's markup gone.

- **Chrome is detected by tag, by role _and_ by class token.** `header`, `nav`, `footer`, `aside`; `role="banner"`, `"navigation"`, `"contentinfo"`; or an id/class **token** matching `CHROME_HINTS` (`site-header`, `main-nav`, `topbar`, …). Whole tokens, never `\b`, which matches at a hyphen and made `hero-banner`, `card-header` and `nav-tabs` chrome. Bare `banner` is not a hint: it is as often a promotion as a masthead.

## Measured against the precedent

Run against the live `k9solutions.uk` home page — 21,213 bytes, minified, longest line 17,405 characters — the cut finds **11 regions**: `topbar`, `site-header` and `footer` as chrome, and `hero`, `trust-strip`, `help`, `services`, `location`, `approach`, `reviews`, `enquire` as sections. That is, allowing for the live page's class names differing from the partial filenames, the same structure the hand conversion chose. This measurement predates the htmlparser2 tokenizer and the never-add-whitespace printer; re-run it before quoting it again.
