The folders v2 reads

v1 shipped two folder keys no module ever read: root and static. They were in the defaults, in the docs and in the README, so a project could point one somewhere and get silence. v2 removed both.

This instance's resolved folders

Read straight off kiss.config.folders — the page cannot claim a key the engine does not have.

keyvalue
src.
pages./pages

Where static went

Nowhere — it never worked. Static files are copied from folders.assets, and .copyAssets(source, target) handles a second directory. This site's stylesheet comes from _shared/assets that way.

Where root went

The only root that matters is per page, not per site: the layout's root hash — "", "../", "../../" — set by each page in its extend call, so links work from the dev server and straight off the file system. The pages under shelf/ set it; this one does not.

A leftover key is just unread

resolveFolders spreads user folders in, so a root: left in a migrated config passes through untouched and nothing reads it. Delete it — an unread key in a config is a lie about what the build does.

How this example works

Every folder above except build, layouts and assets was derived from folders.src. Naming one explicitly beats the derivation, which is how this site keeps its own pages, partials and controllers while borrowing the layout and the stylesheet from _shared.
