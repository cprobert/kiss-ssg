Two sources, one path

The catalogue and the roasting bench both describe coffees, and both fan out into shelf/. One name appears in both. v1 wrote whichever page came last; v2 fails the build naming the path, because only one of the two would ever exist on disk.

The catalogue owns its slugs

  • Arch Blend — Brazil and Peru
  • Guji Uraga — Ethiopia

Bench lots, after the filter

  • Oak Cascara — Bolivia

Dropped before registering

  • guji-uraga — A second sample of the same lot, roasted lighter.

Registered, this would have failed the build with Page already processed: …/shelf/guji-uraga.html.

const claimed = new Set(catalogue.map((item) => utils.toSlug(item.name)))
const benchToBuild = benchLots.filter(
  (item) => !claimed.has(utils.toSlug(item.name)),
)

Four lines, and the priority is now written down rather than implied by registration order. That is the real gain: v1's behaviour depended on which .pages() call came last, which no reader of the script could see.

How this example works

Both fan-outs share one view, shelf/item.hbs, and one controller file, controllers/shelf-item.js, which derives each slug with utils.toSlug — the same function the deduplication uses, so the Set and the output paths cannot disagree.
