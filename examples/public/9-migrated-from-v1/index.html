Example 9 · migrated from v1

The v1 → v2 recipes, as one site that builds

Every recipe in llms.txt § Migrating from v1 has a page here, and this site is the after: it builds clean and exits 0. Where a recipe is about a v1 failure mode, the page demonstrates what v2 does with the case guarded — the point is to show the shape you migrate to, not to leave a broken build lying around.

Await complete()

A chain that ends at generate() exits 0 on a broken build. v2 rejects, and the post-build work moves into a function both branches call.

The folders v2 reads

folders.root and folders.static are gone. Here is the resolved folder table, read off the instance itself.

One Handlebars per instance

Helpers and partials belong to kiss.handlebars. A helper reading the global module renders nothing, quietly.

Dynamic partials

A partial name that resolves to undefined. v2 names the key and the view in a warning; the guard keeps the page.

Two sources, one path

Duplicate output paths fail the build in v2. Dedupe the slugs before registering and decide which source wins.

Controllers that return

A controller that mutates an object model in place drifts a little further on every rebuild. Return new values instead.

The smaller changes

Node 22.12, ESM, the utils named export, export default controllers, and when the generate callback fires.

How this example works

One script, 9-migrated-from-v1.js, builds all of this. Read it beside the pages: each recipe is a few lines with a comment naming the v1 idiom it replaces, and the page it built explains what changed and why. The two .pages() calls at the bottom are the deduplication recipe doing real work — they fan out into one shelf/ folder without colliding.
